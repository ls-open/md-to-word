七份样例不是"效果图"，而是这套引擎的**最终验收面**。每一份都真导出、真用 Word 打开核对过；
这七份跑出来没问题，用户按同样的写法用，也不该有问题。所以样例的覆盖面本身就是一条约束：
新加一种写法，就要在下面这张表里落一格，否则等于没验收。

## 预设验收（新增或修改内置预设时）

预设不是「看起来像」：每个数值都要有出处，并且落到产物里能被复核。

1. **官方来源**：标准条款、期刊作者指南或官方样张的 URL 与确切数值；找不到就写「未核实」，不要编。
2. **真实样张**：`demo/<编号>_<名称>/` 里放一份能导出的稿件与 README，README 写明覆盖什么、不覆盖什么。
3. **产物断言**：在 `tests/test_presets_official.py` 里加官方数值断言（页面几何、字体字号、行距、缩进、页码位置、表格线）。通用层会自动检查每个预设的纸张与页边距。
4. **Word / WPS 打开核对**：XML 对了不等于版面对了；目录、页码、跨页表与图片落版要用真 Word 看一遍。
5. **已知差异清单**：做不到的（双栏、红头、run-in 标题、自动编号）写在预设注释与 demo README 里，不假装支持。
6. **登记**：`tests/test_demos.py` 的 `CASES`、`demo/README.md` 的覆盖表、`tests/test_bilingual_spec.py` 的预设名单。

## 维护约定

- **样例只增不改**：改一句正文就可能让版面重新分页，而截图、页数、耗时都跟着变。
  需要演示新写法时，优先在现有样例里加一段；确实放不下再加一份新的。
- **导出用 `bash scripts/export.sh`**，加 `--pdf` 出核对版；页面图由 `pdftoppm -r 110` 生成。
- **改了样例就要重出截图**：`page-*.png`、`.pdf`、`.docx` 都随样例一起提交，README 直接引用它们。
- `make_demo_figures.py` 负责流程图与耗时图：它现场跑导出取真实耗时，图中的数字不是手写的。
