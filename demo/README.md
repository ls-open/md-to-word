# 样例：既是展示，也是验收面

四份样例不是"效果图"，而是这套引擎的**最终验收面**。每一份都真导出、真用 Word 打开核对过；
这四份跑出来没问题，用户按同样的写法用，也不该有问题。所以样例的覆盖面本身就是一条约束：
新加一种写法，就要在下面这张表里落一格，否则等于没验收。

## 每份样例演示什么

| 目录 | 定位 | 看什么 |
|:--|:--|:--|
| `00_quickstart` | 最小样例，一页纸 | 从二十来行 Markdown 到成品的最短路径；三线表、代码块、行内代码 |
| `01_chinese_thesis` | 中文学位论文 | 摘要关键词、目录域、分节与小写罗马页码、脚注、公式按章编号、双线章名页眉、跨页表头、**参考文献之后接附录**（文献条目插在 `%% 参考文献标题` 之后，不押到文末） |
| `02_modern_report` | 企业技术白皮书 | 全网格表、引用块（含列表）、有序/无序/嵌套列表、代码块、彩色一级标题、图与表交叉出现 |
| `03_english_paper` | 英文期刊投稿 | 英文摘要、APA 作者-年份制、图题在下、`Equation 1` 形式的交叉引用 |

## 维护约定

- **样例只增不改**：改一句正文就可能让版面重新分页，而截图、页数、耗时都跟着变。
  需要演示新写法时，优先在现有样例里加一段；确实放不下再加一份新的。
- **导出用 `bash scripts/export.sh`**，加 `--pdf` 出核对版；页面图由 `pdftoppm -r 110` 生成。
- **改了样例就要重出截图**：`page-*.png`、`.pdf`、`.docx` 都随样例一起提交，README 直接引用它们。
- `make_demo_figures.py` 负责流程图与耗时图：它现场跑导出取真实耗时，图中的数字不是手写的。
