# md-to-word 手册

期刊论文、课程报告、技术方案、学位论文，都在这一份里。学位论文多出来的部分见 §9。

English: `manual_en.md`

Markdown → 规范 Word（`.docx`）。内容与排版分离：Markdown 是源，格式全部声明在格式文件里；
导出是确定性的：同一平台上，同一份源任何时候重跑，产物逐字节一致（跨平台的差异见 §6 末尾）。

`md-to-word --contract` 打印契约速查、入门文档与本文件的绝对路径、内置预设路径。

一次导出由**三层输入**配合完成（第三层可选）：

| 层级 | 文件 | 管什么（Agent 决策基准） |
|:--|:--|:--|
| **1. 内容与行内样式** | 稿件 `*.md` | 正文、标题分级（`#`）、结构标记（`%% 样式`、`{{< toc >}}`、`{{< section >}}`、`$$…$$ {#eq-}`）、YAML（`bibliography:`、`csl:`、`crossref:`），以及**行内局部格式**（`**加粗**`、`*斜体*`、`~~删除线~~`、`[文字]{.underline}`、`^上标^`、`~下标~`、`` `代码` ``、`[文字](url)`、`[^1]`）。 |
| **2. 样式与页面规约** | 格式 `*.txt`（不传 `-f` 时只认同目录 `format.txt`，否则用内置预设） | 页面几何（`纸张`、`页边距`、`装订线`、`对称页边距`）、校对与排版（`校对语言`、`标点压缩`）、页眉页脚与页码，以及**样式级**外观（字体、字号、段落颜色 `颜色#RRGGBB`、行距、缩进、三线表/全网格线）。 |
| **3. 前置底模** *(可选)* | `--base-template 底模.docx` | 仅在需要保留已有 `.docx` 封面、徽标、签字页等固定版式时使用（`--keep-until` / `--cover-sections`）。底模贡献前置几节、主题与默认字体；文档级设置必须与格式一致（§9.3）。 |

判断原则：**局部微调（某几个字加粗、斜体、上下标）写在 Markdown 里；整类段落或页面参数（字体、行距、样式级颜色、装订线、双面镜像、标点压缩）写在 `format.txt` 里；复杂图形封面靠 `--base-template` 保留；只有三层加起来都做不到的项（合并单元格、行内改文字颜色、多栏、浮动环绕图）才需导出后在 Word 里补。**

这本手册分两层：**常用路径**是照做就能出稿的五章；**参考**按需查，平时不必通读。
第一次用：§1 装、§2 写稿、§3 改格式、§5 导出，有文献再加 §4。长尾问题由预检和导出时的
错误直接指出（带行号与应写形式），手册不逐条罗列。

## 1. 入口与退出码

| 入口 | 用法 |
|:--|:--|
| 命令行 | `md-to-word 稿件.md -o 输出.docx` |
| Python | `from md_to_word import export` |
| 从参考 `.docx` 反推要求草稿 | `md-to-word-template 参考.docx -o format.txt` |
| 入门文档 | 包内 `guide.md`（中文环境打印 `guide_zh.md`）：按什么顺序做、门禁怎么读、边界在哪。只装了包时先读它：`md-to-word --guide` 直接打印 |
| 从零起步 | `md-to-word init [目录]`：生成 `format.txt` 与一份能直接导出的 `hello.md` |

```bash
md-to-word 稿件.md -o 输出.docx                      # 内置中文预设 zh-academic
md-to-word 稿件.md --preset zh-tw-academic -o out.docx # 繁体中文学术预设（zh-TW，标点不压缩）
md-to-word 稿件.md --preset zh-report -o out.docx    # 中文现代技术报告预设
md-to-word 稿件.md --preset en-nature -o out.docx    # 英文期刊预设
md-to-word 稿件.md --preset zh-gb9704 -o out.docx    # 党政机关公文正文版式（不含红头/版记）
md-to-word 稿件.md --preset en-apa-student -o out.docx # APA 7 学生论文
md-to-word 稿件.md -f format.txt -o out.docx        # 显式指定格式文件
md-to-word init                                     # 生成 format.txt 与可直接导出的 hello.md
md-to-word 稿件.md --validate-only                  # 预检 + 临时试导出，不写目标 .docx
md-to-word --guide                                  # 入门文档（代办流程、门禁、边界）
md-to-word --contract                               # 契约速查 + 手册与预设路径
md-to-word --contract --lang en                     # 同上，英文版（样式名用英文写法）
md-to-word --contract --json                        # 同一份契约的机器可读版本（给 Agent）
md-to-word 稿件.md -o 输出.docx --verbose            # 逐样式明细，排查「格式没生效」
md-to-word 论文.md --base-template 底模.docx --cover-sections 3 -o 论文.docx   # 见 §9.3
```

**格式要求三选一**：`-f` 显式指定；稿件同目录有 `format.txt` 就用它；否则用内置预设——未传
`--preset` 时**按稿件语种选**：中文稿 `zh-academic`，其他语种 `en-nature`。预设清单与各自版式见 §3.3。
除 `format.txt` 之外不猜：**没有 format.txt 时**，同目录另有 `.txt` 会在提醒里点名，要用就加 `-f`。
用了哪一份，`--json` 的 `format_source` 会写明（`file:` 或 `preset:`）。

`--lang` 只决定**消息语言**。默认预设按**稿件语种**选（中文 `zh-academic`，其他 `en-nature`）；
默认 CSL、交叉引用前缀与公式编号外观按 **doc_lang**（格式文件写了「校对语言：」时以它为准，
否则按正文语种）。两者都不随 `--lang` 变。稿件、格式文件与
`.bib` 支持 UTF-8（含 BOM）、UTF-16 与 GB18030；读到非 UTF-8 时会提醒另存为 UTF-8，便于 Git 比对与跨平台协作。

**退出码**：`0` 完成；`1` 稿件、门禁或依赖问题；`2` 参数用法错误；`3` `.docx` 已写出但 `--pdf` 未渲染（非 macOS、没装 Word，或 Word 启动失败）。
`0` 表示已通过全部闸门，**不等于版面已经肉眼核对过**（§5.3）。

**`--json`**：给程序与 Agent 用。stdout 只有一行 JSON，进度与报错仍走 stderr：

```json
{"ok": true, "returncode": 0, "input": "稿件.md", "output": "…/稿件.docx", "pdf": null,
 "pdf_skip_reason": null,
 "lang": "zh", "doc_lang": "zh", "format_source": "preset:zh-academic",
 "messages": ["…"], "warnings": [], "errors": [],
 "diagnostics": [{"severity": "warning", "code": "gate.heading.level",
                  "file": "…/稿件.md", "line": 7, "message": "…"}]}
```

键名固定、不随版本变；`messages` 与 `errors` 的值是给人读的句子，跟着稿件语种走。
`messages` 含进度、**提醒**与结尾的核对提示（提醒按类合并成一条，最多列 8 个行号），成功时
要转述的内容都在这里，不必再解析 stderr；需要单独识别提醒时读 `warnings`，它是 `messages`
里提醒条目的子集。`lang` 是消息语言；`doc_lang` 是本次采用的文档语言（决定默认 CSL、交叉引用前缀与公式编号
默认外观）：显式格式文件的 `校对语言：` 优先，没有才按正文判定。`pdf_skip_reason` 在
`--pdf` 未生成时给出原因码（`no-word` / `not-darwin` / `no-render-script` / `timeout` / `word-error` 等），成功时为 `null`。
`format_source` 是 `file:/绝对路径` 或 `preset:zh-academic`。解析方读键，不读措辞。

`diagnostics` 是同一批结论的结构化版本，每条固定五个键：`severity`（`error` / `warning`）、
`code`（稳定标识，如 `gate.image.missing`）、`file`、`line`（没有单一位置时为 `null`）、
`message`。**按 `code` 分支**，`message` 只用来展示。`--contract --json` 给出完整契约：
版本、guide/手册路径、预设路径与 `sha256`、中英样式名、YAML 键、块级标记、图片格式、
退出码，以及 `--json` 的键集。参数用法错误（退出码 `2`）发生在参数解析阶段，此时不产出 JSON。

**库调用**：

```python
from md_to_word import export

result = export("稿件.md", "输出.docx", preset="zh-academic")
if not result.ok:            # ok = docx 已写出（--pdf 跳过不算失败）
    raise SystemExit("\n".join(result.errors))
print(result.output_docx)    # result.messages 是进度与提醒
```

## 2. 稿件契约

稿件是普通 Markdown 加三条约定：标题用 `#`，段落样式用 `%%`，带编号公式用 `{#eq-}`。
**不存在「任意 Markdown 直接生成成品」的路径**：不符合契约时导前预检中止并指到行号，不会产出
外观正常但格式没映射上的文档。

### 2.1 标题与层级

- 文档主标题写一行 `%% 文档标题 主标题`，位置由这一行决定（可排在封面之后）；副标题、作者、
  日期同理，各写一行 `%% 副标题` / `%% 作者` / `%% 日期`。**YAML 里不写这四项**，写了会被预检拦下。
- 正文从 `#` 起是各级章节标题，层级连续不跳级。
- 某条标题（如「致谢」）要沿用 `#` 的大纲结构或按章编号，但**不进目录**，可在行尾写 `{.unlisted}` 或 `{不入目录}`（如 `# 致谢 {不入目录}`）；它仍保留同级外观，但不会触发 `{样式标题:Heading 1}` 页眉更新（需单独换页眉时可用 `{{< section >}}` 切节）。
- 标题自带阿拉伯数字编号时（`1.`、`2.1`、`2.1.1`），编号深度等于 `#` 的数量。

### 2.2 段落样式行 `%%`

需要单独指定样式的段落，在**行首**写 `%% 样式名 正文`：

```markdown
%% 摘要标题 摘要

%% 摘要 本文提出一种方法……

%% 关键词 关键词：甲；乙；丙
```

- 符号、样式名、内容同行；**一行即一段，空行结束**，没有闭合符号——与 `# 标题` 是同一条排布规则。
- 为什么标题能用符号、段落不能：标题层级只有六种，`#` 的数量就能编码；段落样式有三十多种，
  符号编码不了，所以名字写在符号后面。
- 样式名取自 §3.4 的封闭词表，写错带行号报错。**标题类（`一级标题` 等）不能写在此处**，层级只由 `#` 定。
- `参考文献` 也不能写：文献列表由文献库（`.bib` 或 CSL-JSON）生成，**插在 `%% 参考文献标题` 那一行之后**（直接写
  `# 参考文献` 或 `# 参考文献 {.unlisted}` 也认），所以文献后面可以正常接附录、致谢。
- `%% 摘要标题` 与 `%% 参考文献标题` 是否进目录、是否接入 `{样式标题:Heading 1}` 动态页眉，由格式文件里的
  `加入目录` / `不入目录` 与 `加入页眉` / `不入页眉` 显式声明（无隐式升级）；写 `加入页眉` 时借用 `Heading 1`
  供页眉的 `{样式标题:…}` 域识别，外观仍完全按该行声明写出。`不入目录` 与 `加入页眉` 不可同写。
- 所有块级元素（`$$` 公式、表格首行、独立图片行、短代码、`%%` 行）与相邻正文之间**必须隔开空行**，
  §2.5 给了哪一侧必须空的对照表；`%% 表题` 可直接贴住表格首行。

### 2.3 公式

**只有一种编号写法**：`$$…$$ {#eq-标签}`，编号由写出器按出现顺序生成。

公式里的裸 `%` 是 LaTeX 的注释起始符，**它后面整段内容会被丢掉**；字面百分号写 `\%`
（预检会拦下裸 `%`）。行内公式 `$…$` 与独立公式 `$$…$$` 的转义规则完全一致。

正文里的**变量、符号、数学式**用行内公式 `$x$` 写：反引号 `` `x` `` 落的是等宽代码字体（§2.6），
排出来不像正文。

```markdown
$$Y_{ij} = \alpha_0 + \beta_1 X_{1,ij} + \varepsilon_{ij}$$ {#eq-model1}
```

- 正文引用写 `@eq-model1`，渲染前缀按文档语言（doc_lang）自动取：中文「式」，其它「Equation」。
  **交叉引用不加方括号**：`[@eq-model1]` 是引文写法，会被当成一条文献去查，预检会拦下来并提示改成 `@eq-model1`。
  **前缀由引擎加**，正文写「见 @eq-model1」即可，写成「见式 @eq-model1」会得到「见式 式（1）」。
  要改前缀就在 YAML 里显式写 `crossref:`（§2.7），写了以 YAML 为准。
- **按章编号**（学位论文的 `（2-1）` 而非 `（1）`）：YAML 里 `crossref:` 换行缩进一行
  `chapters: true`。**写成一行 `crossref: chapters: true` 不是合法 YAML**，解析会直接失败。
  章号取公式所属一级标题的序号，不读标题里手写的数字。
- **编号外观**：格式文件写一行 `公式编号格式：（{c}-{n}）`——`{n}` 是序号（必写）、`{c}` 是章号（可选）。
  不写按文档语言给默认：中文 `（5-1）` / `（1）`，英文 `(5.1)` / `(1)`。公式旁的编号与正文里的
  `@eq-x` 用同一份格式渲染，不会一处带括号一处不带。
- **附录单独编号**：`# 附录A 实验数据`、`# 附录2 补充推导` 这类一级标题按**附录章**处理——
  `{c}` 取标题里那个标识（A / 2），附录内的序号重新从 1 起；标题没写标识时按出现顺序给 A、B、C。
  学校要「（附2-1）」这种前缀，就再写一行 `附录公式编号格式：（附{c}-{n}）`（不写沿用正文那套）。
  附录**不占正文章号**：附录前的六章仍是 1~6，附录后的「致谢」接着是第 7 章。
- 无编号公式直接写 `$$…$$`：不编号也不占号。写了标签但不引用是允许的，编号照出。
- **公式段落的段前/段后跟正文样式**：`format.txt` 的 `正文：` 行写 `段前`/`段后`，公式就跟着用。
  正文是固定行距（`行距20磅`）时，公式段自动改成同值的“最小值”，让高公式自己撑开，不会压住上下文字；
  单倍/倍数行距不写任何直接格式。
- 间距命令 `~` `\,` `\:` `\;` `\quad` `\qquad` 都保留（`~` 与 `\ ` 是不换行空格）；数学模式里的
  普通空格照 LaTeX 的规矩不排版。
- **多行公式**用 `cases`、`matrix`、`split` 环境（`aligned` 自动按 `split` 处理）。花括号不配对时
  转换器不报错、只会静默丢内容，预检按行拦下。
- **不要写 `\tag{…}`**：整条公式会退化成字面文本打进 Word，预检会拦下并给改写示例。

### 2.4 图、表与题注

| 元素 | 写法 | 落到的样式 |
|:--|:--|:--|
| 表格题注 | 表格上方一行 `%% 表题 **表 1** 各方案对照` | `Table Caption` |
| 表格注释 | 表格下方一行 `%% 表注 注：…` | `Table Note` |
| 图片 | `![](path/img.png){width=14cm}` | `Captioned Figure` |
| 图片（按版心百分比） | `![](path/img.png){width=50%}` | `Captioned Figure` |
| 图片（PDF 矢量图） | `![](path/fig.pdf){width=14cm}` | `Captioned Figure` |
| 图片题注 | 图片上方或下方一行 `%% 图片题注 图 1 系统架构` | `Image Caption` |

- 题注是**独立段落**，不是表格或图片的附属字段；行首 `%%` 是唯一的样式入口。「题注与图表同页」
  由写出器给这一对里的前一件补「与下段同页」实现，与题注样式是否声明无关（Word 只有这一个方向）。
- 图片行只描述图片本身：方括号里放无障碍替代文字，`{width=…}` 按版心钳制（超宽会被钳到版心宽，
  并出一条提醒）。宽度可写绝对长度（`cm` / `mm` / `in` / `pt`）或相对版心的百分比（`{width=50%}`）；
  百分比超过 100% 会被钳成满宽并提醒。
- **图片可以直接引用 PDF**（matplotlib、MATLAB、Origin、Visio、TikZ 的默认导出格式）：导出时按声明
  宽度的 300 dpi 渲染第 1 页；多页只取第 1 页并出提醒。位图支持 `.png`、`.jpg/.jpeg/.jpe/.jfif`、
  `.gif`、`.bmp`、`.tif/.tiff`；Word 放不下的 `.svg`、`.webp`、`.eps`、`.emf`、`.wmf` 在预检拦下。
- **图片不要加 `{#fig-xxx}` 标签**：图片行只认 `width`，其他属性会被预检拦下（§2.8）。图号手写在题注文字里即可。
- 题注内部的局部排版直接写在正文里（`**表 1**` 加粗编号、`*Title*` 斜体题名），导出后忠实保留。
- 列宽默认不动（按内容排）。**要定列宽比例，就把分隔行的短横线写得长短不一**（`|:--|:--|:------|`
  约 2:2:6，按版心铺开；只数短横线）。写成一模一样 = 没指定，也因此无法强制等宽。
- 分隔行的冒号声明**该列**的对齐（`:--` 靠左、`:--:` 居中、`--:` 靠右）；**不写冒号就是「不表态」**，
  这一列按 `紧凑：` 的对齐排。冒号是显式表态，写在哪一列就覆盖哪一列的 `紧凑：`。
- 表要带首尾竖线（`| 甲 | 乙 |`），不带外框的写法认不出。

### 2.5 块级标记

只承认三种，**独占一行**且与正文隔空行：

| 标记 | 作用 |
|:--|:--|
| `{{< pagebreak >}}` | 分页 |
| `{{< toc >}}` / `{{< toc 2 >}}` | 目录域；收几级由格式文件的 `目录N级` 决定，写数字则直接指定（最多五级；写 N 就要有对应的 `目录N级`） |
| `{{< section >}}` | 普通分节；这一节的外观用格式文件的全局设置 |
| `{{< section 正文 >}}` | 给**下面这一节**命名；页码格式、页眉、页脚由格式文件里这个名字的声明决定 |

**节名不是参数，是名字。** 格式文件里先写一行「分节：正文」声明它，再按需要写
「正文页码：小写罗马 起始1」「正文页眉内容：…」「正文页脚内容：无」；稿件只负责说这是哪一节、
从哪里开始。`zh-academic` 与 `zh-tw-academic` 预设已经声明了封面 / 前置 / 正文 / 附录，可以直接用；用了没声明的
节名会在导前报错，并列出可用的节名。

- **它命名的是「它下面那一节」**：要收尾前置件，就在目录之后、第一章之前写
  `{{< section 正文 >}}`；封面之后写 `{{< section 前置 >}}`，前置件就按前置的页眉页脚与页码排。
- **出现在文档最前面时**，它直接给第一节命名，不会凭空多出一节空白页。
- **后面不要再写 `{{< pagebreak >}}`**：分节符已自带「下一页」，叠加会多顶出一页（预检会提醒）。
  单节文档（报告、技术方案）通篇阿拉伯页码即可，不需要这个标记。

- 这三个标记是本工具自己的语法，只在本工具里有效。
- `\newpage` / `\pagebreak` / `\clearpage` 在 docx 里不生效。
- 目录用**域**而不是静态列表：页码要 Word 现算。打开时自动更新一次，**要完全准确需再按一次 F9**。
- 进目录靠**大纲级别**：`#` 标题天然有（单条标题可在行尾加 `{.unlisted}` 或 `{不入目录}` 排除）；非标题类节段样式用 `加入目录` / `不入目录` 控制（不能写在正文类或 `一~六级标题` 上）。

**哪一侧必须空行**（按标记各异，已逐例核对产物）：

| 标记 | 相邻会出事的一侧 | 后果 |
|:--|:--|:--|
| `$$…$$` 公式 | 后 | 后一行标题/正文被并进同一段 |
| `{{< pagebreak >}}`、`{{< toc >}}`、`{{< section … >}}` | 后 | 同上 |
| 独立图片行 | 前、后 | 前：并进上一段，样式跟着上一段走；后：标题被并进图片段 |
| 表格首行 | 前 | 表格退化成字面文本 |
| 标题、围栏尾行、表格末行 | 无 | 两种粘法都无害 |

### 2.6 列表、引用块、代码与行内格式

- **列表**：`- ` / `1. ` 落 `正文` 样式，编号与缩进由引擎的三级编号定义决定（在 Word 里回车、
  改级别、换编号形式都还能用）；**缩进两格就是下一级，最多三级**，第四级起并入第三级。
  引用块里放列表同样支持。
- **引用块**：`> ` 照常写；格式文件需声明 `引用块：` 样式行（内置预设已含）。
- **代码块**：``` 围栏落 `SourceCode` 样式，底模已给等宽字体、清零缩进、单倍行距、左对齐，
  **不写 `代码：` 也正常**；要改字号字色才写。行内 `` `code` `` 走 `VerbatimChar` 字符样式，
  字体在底模里定为 Consolas/宋体、**不在格式文件里**——要改就在 Word 里改这个字符样式。
- **脚注**：正文写 `[^1]` + `[^1]: 注释文字` 即可，**不必在格式文件里声明**（不写就按正文推定：
  字体对齐跟正文、字号降一档、单倍行距、序号上标）。脚注里可写行内格式、链接与引文；**公式暂不支持**，
  会整篇失败并说明，不会静默印成普通文字。
- **行内格式直接写在正文里**：`**加粗**`、`*斜体*`、`~~删除线~~`、`[下划线]{.underline}`、`H~2~O`、
  `x^2^`——渲染器直接写成字符属性，不需要在格式文件里声明，也不与样式级设置冲突。
- **星号要看两头**：`(1*S*,2*R*)`、`y = 4054.1*x*` 出斜体；只有开闭符**两头都紧挨字母数字**才当乘号
  （`2*3*4`、`a*b*c`）原样印出——CommonMark 会读成斜体，本工具故意不跟。字面星号写 `\*`（反斜杠转义，ASCII 标点通用），没解析的预检会提醒。
- **段落与换行**：**一行一段**，相邻的普通行不会被合并——一行一句的短段落是正常写法，各自还能
  挂 `%%` 样式。同一段落内部要换行（地址、诗句、长标题），在行尾写一个 `\` 或两个空格，写出时
  落成段内换行，段落属性仍是一套。**多行地址只写一个样式行**：

  ```markdown
  %% 作者 北京大学计算机学院\
  北京市海淀区颐和园路 5 号\
  100871
  ```

  后两行不写 `%%`，它们接续第一行，最终仍是一个段落、一套样式。疑似折行（上一行没有句末标点、
  本行紧随其后）同类合并成一条提醒并给出行号；本意是短段落时不必处理。
- **字体自由指定**：任意本机已安装字体（`仿宋`、`仿宋_GB2312`、`方正小标宋简体`、`微软雅黑`、`楷体`）。

### 2.7 稿件头部：YAML 只放与位置无关的配置

判据只有一条：**YAML 没有位置**。凡是「落在哪一页、哪一段」由作者决定的内容，一律写正文的样式行。
标题尤其如此——它可能在第一页第一行，也可能排在封面之后；写在 YAML 里就只能是前者。

| 元素 | 写法 |
|:--|:--|
| 文献库、CSL 样式 | YAML `bibliography:` / `csl:` |
| 交叉引用前缀、按章编号 | YAML `crossref:`（`eq-prefix`、`chapters`；图片/表格交叉引用暂不支持） |
| 引文是否加超链接 | YAML `link-citations:`，默认开启；写 `false` 时文内引用不带内链（文献表的书签仍保留） |
| 标题、副标题、作者、日期、摘要、关键词、文献区标题 | 正文样式行，见 §2.1、§2.2 |

```markdown
---
bibliography: references.bib
csl: apa.csl
---

%% 文档标题 标题

%% 作者 张三

%% 摘要 摘要正文……
```

> **YAML 里写 `title` / `subtitle` / `author` / `date` / `abstract` / `keywords` 会被预检拦下**，
> 报错直接给出该写成哪一行。这不是兼容性缺口：标题被钉死在第一页、或一段摘要静默丢掉，
> 都比报错难查得多。唯一例外是 `reference-section-title`，只提醒不拦。

### 2.8 不支持的写法

这些写法不会报错，只会把原始语法原样印进 Word，因此预检一律拦下并给出替代写法：

HTML 标签与 `<https://…>` 自动链接、横向分隔线 `---`、`====` 下划线式标题、定义列表、
待办勾选框 `- [ ]`、首尾不带竖线的表格、引用块套引用块、全角 `％％`、四空格缩进代码块、
跨行行内公式、列表项的第二段（空行 + 缩进）、紧跟列表项的围栏代码块（中间不空行，见 §6）、`#` 后面没空格的标题、
只有 `#` 没有文字的标题、图片行里 `width` 之外的属性（如 `{align=right}`）、
Word 放不下的图片格式（`.svg`、`.webp`、`.eps`、`.emf`、`.wmf`，
请另存为 PNG 或直接引用 PDF）、`==高亮==`、`[文字]{.类名}`（`.underline` 除外）、
`\(…\)` 行内公式（请写 `$…$`）、`\[…\]` 块级公式（请写 `$$…$$`）、引用式链接 `[文字][ref]` 与定义行 `[ref]: url`（请写 `[文字](url)`）。

## 3. 格式文件

格式文件（下文示例统一叫 `format.txt`，文件名随意）是一门小语言：一行一种样式，行内属性写全。规矩三条：

1. **单行属性写全**：每条样式行必须写齐 `字体 字号 [加粗/不加粗 倾斜/不倾斜] 对齐 行距 段前N磅
   段后N磅 首行缩进N字符`。没有段间距或缩进时，**也要显式写** `段前0磅 段后0磅 首行缩进0字符`。
2. **按结构成套拼装**：基础五条所有文档都要（§3.4）；表格 / 图片 / 摘要关键词 / 参考文献 / 目录 /
   引用块 / 脚注按稿件实际出现的结构成套加上。用到了却漏写，导前预检会报。
3. **从预设起步**：不要在空白里写。复制内置预设（`md-to-word --contract` 给出路径）到稿件旁，
   只改用户明确提到的那几行。

**注释**：整行 `#` 是注释；**行内 `#` 不是**——`正文：宋体 小四 #加粗` 里的 `#加粗` 会被当成
没见过的词报错（唯一的行内 `#` 用法是颜色，`颜色#1F4E79`）。

### 3.1 词表（每个属性只有一种写法）

样式行格式 `<样式名>：<属性1> <属性2> …`（冒号 `：` 或 `:` 皆可）。**关键词仅认简体中文与英文（不收繁体键名**，写繁体文档时键名仍写简体或英文，例 `纸张：A4`、`校对语言：zh-TW`，正文 `.md` 本身繁体/简体/英文皆可）。**表外的词一律报错并指出行号**——解析是整词消费：认不出的词会被指出，既不静默丢弃、也不会被别的规则读错。

| 属性 | 唯一写法 | 示例 | 错误写法（会被报错） |
|:--|:--|:--|:--|
| 字体 | `<中文字体>/<西文字体>` 或单字体 | `宋体/Times New Roman` | — |
| 字号 | `<数字>pt` 或中文号数 | `12pt`、`小四`、`三号` | `12磅`、`12`（无单位） |
| 加粗 | `加粗` / `不加粗` | `加粗` | — |
| 倾斜 | `倾斜` / `不倾斜` | `倾斜` | `斜体`、`中等倾斜` |
| 对齐 | `居中` / `左对齐` / `右对齐` / `两端对齐` | `左对齐` | `靠左`、`靠右`、`分散对齐` |
| 颜色 | `颜色#<六位十六进制>` | `颜色#1F4E79` | `颜色深蓝`（颜色名在不同设备上解释不一，只收色值）；行内 `{color=…}` 无效 |
| 行距（倍数） | `行距<数字>倍` | `行距1.25倍` | `1.5倍行距`、`单倍行距` |
| 行距（固定值） | `行距<数字>磅` | `行距20磅` | `行距固定值20磅`（死钉在 N 磅，内容比它高会被裁掉） |
| 行距（最小值） | `行距最小值<数字>磅` | `行距最小值25磅` | `最小行距25磅`——当场报错并给应写形式 |
| 段前 / 段后 | `段前<数字>磅` `段后<数字>磅` | `段前0磅 段后6磅` | — |
| 缩进（必填，每行只能一种） | `首行缩进<数字>字符`（中文）/ `首行缩进<数字>英寸`（英文）/ `悬挂缩进<数字>英寸` | `首行缩进2字符`、`首行缩进0字符` | `首行缩进1厘米`、**同行既写首行缩进又写悬挂缩进** |
| 左缩进 | `左缩进<数字>字符` | `左缩进2字符` | `缩进2字符`、`左缩进2厘米` |
| 点线制表位 | `点线制表位` | 手打的行加它，行尾页码右对齐 + 点线引导 | 写位置数字；写在 `目录一/二/三级` 上不生效 |
| 分页控制 | `与下段同页`、`段前分页`、`段中不分页`、`孤行控制` / `取消孤行控制` | `一级标题：… 与下段同页 段前分页` | — （`段前分页` 比手写 `{{< pagebreak >}}` 稳，内容增删后仍自动从新页开始） |
| 目录收录 | `加入目录` / `不入目录` | `参考文献标题：… 加入目录`、`摘要标题：… 不入目录` | 声明了目录样式时，`摘要标题` 与 `参考文献标题` **联动必填**其一；不可写在正文类（`正文`/`首段`/`普通`/`紧凑`）或 `一~六级标题`（`#` 标题单条排除见 §2.1） |
| 页眉收录 | `加入页眉` / `不入页眉` | `参考文献标题：… 加入页眉`、`摘要标题：… 不入页眉` | 页眉写了 `{样式标题:Heading ...}` 时，`摘要标题` 与 `参考文献标题` **联动必填**其一；不可与 `不入目录` 同写，亦不可写在正文类或 `一~六级标题` |
| 跨页重复 | `跨页重复` | `表头：… 跨页重复` | 写在 `表头：` 以外的样式行（它描述的是表头行） |
| 无边框 | `无边框`（去掉底模自带下边框） | `文档标题：… 无边框` | `下边框无`——与 `无边框` 产物逐字节相同，故只留一种写法 |
| 下边框 | `下边框<单线\|双线\|等宽双线\|上粗下细\|三线>` `[边框粗<N>磅]` | `页眉：… 下边框双线 边框粗1.5磅` | 写 `下划线`（那是字符属性）；`边框粗` 单独写（没有下边框时无处可落） |
| 字符间距 | `字距<N>磅`（正加宽、负紧缩） | `字距0.5磅`、`字距-0.2磅` | `字间距0.5磅`（词序反了） |
| 纸张 | `纸张：<A4\|Letter>`（不写默认 A4） | `纸张：A4` | `纸张：B5` |
| 页边距 | `页边距：上<N>cm 下<N>cm 左<N>cm 右<N>cm` | `页边距：上2.54cm 下2.54cm 左2.54cm 右2.54cm` | — |
| 装订线 | `装订线：<N>cm` | `装订线：1cm` | 版心宽度会减去装订线（开 `对称页边距` 时自动留在每页内侧） |
| 对称页边距 | `对称页边距：<开\|关>` | `对称页边距：开` | 双面印刷用：启用后 `页边距` 的左右分别作内侧/外侧边距 |
| 页眉 / 页脚距边界 | `页眉距边界：<N>cm` / `页脚距边界：<N>cm` | `页眉距边界：1.40cm` | — |
| 文档网格 | `文档网格：每页<N>行` | `文档网格：每页22行` | 上限是「版心高 ÷ 正文行高」（小四 1.3 倍 = 34 行），超过会提醒；**「每行多少字」不设开关** |
| 西文字体 | `西文字体：<字体>`（全局默认西文） | `西文字体：Times New Roman` | — |
| 校对语言 | `校对语言：<语言代码>` | `校对语言：zh-CN`、`校对语言：zh-TW` | `校对语言：中文`（不写则按底模英文校对，Word 会把中文整篇标成拼写错误）。**它同时决定默认 CSL、交叉引用前缀与公式编号外观的语种**：显式格式的校对语言优先，没写才按正文判定 |
| 标点压缩 | `标点压缩：<压缩\|不压缩\|压缩含日文假名>` | `标点压缩：不压缩` | 不写时按 `校对语言` 默认：`zh-CN` 压缩，`zh-TW`/`zh-HK`/`zh-MO`/`en-*` 不压缩（保留繁体全角居中标点），`ja-*` 压缩含假名 |
| 表格（含表格时必填） | `表格：<居中\|左对齐\|右对齐> <三线表\|全网格线\|顶底线\|无边框> [线宽上/线宽底/线宽表头下<N>磅] [线宽内<N>磅（仅全网格线）] [单元格垂直居中\|顶端\|底端] [单元格内边距<N>cm] [表后间距<N>磅] [行不跨页]` | `表格：居中 三线表 线宽上1磅 线宽底1磅 线宽表头下0.25磅 单元格垂直居中` | 三线表/顶底线写 `线宽内`（没有内部横线）；无边框写任何线宽；`单元格内边距` 是四边同值、用 cm 不用磅；不写默认左右 0.19cm、上下 0（Word 常规）；`表后间距` 落在表格（含表注）之后 |
| 表内段落 | `紧凑：<段落属性，同样式行语法>` | `紧凑：宋体 五号 居中 …` | — （表内字体字号对齐**只能靠这一行**，不写就继承正文的 2 字符首行缩进） |
| 表头行（含表格时必填） | `表头：<段落属性> [跨页重复]` | `表头：宋体/Times New Roman 五号 加粗 居中 行距1.0倍 段前0磅 段后0磅 首行缩进0字符 跨页重复` | — |
| 表格宽度 | **不用声明**——默认由内容排 | — | 要列宽比例就改分隔行短横线长短（§2.4） |
| 页眉 / 页脚样式 | `页眉：<段落属性>` / `页脚：<段落属性>` | `页眉：宋体/Times New Roman 小五 居中 行距1.0倍 段前0磅 段后0磅 首行缩进0字符` | 把内容写进样式行——字体段是唯一自由文本，`页眉：某某大学 小五 …` 里的 `某某大学` 会被当成字体名静默收下 |
| 页眉 / 页脚内容 | `页眉内容：` / `页脚内容：`，及 `偶数页…` / `首页…`、`正文页眉内容：` 这类按节写法 | `页眉内容：{样式标题:Heading 1}` | `{样式标题:一级标题}`（只认 Word 样式名）；写了内容行（含按节的）却不写对应样式行，判为必填行缺失 |
| 页码格式 | `页码：<阿拉伯\|罗马\|小写罗马\|字母\|大写字母> [起始<N>]` | `页码：阿拉伯 起始1` | `页码：1,2,3`；写了却没有 `{页码}`（页码要印出来得靠页眉页脚内容） |
| 公式编号位置 | `公式编号：<右侧\|紧跟>` | `公式编号：紧跟` | 不写默认 `右侧`（编号靠版心右边） |
| 公式编号格式 | `公式编号格式：<模板>`，`{n}`=序号（必写）、`{c}`=章号（可选） | `公式编号格式：（{c}-{n}）` | 写 `{c}` 而稿件没开 `crossref.chapters`（预检会拦） |
| 附录公式编号格式 | 同上的模板；不写则沿用 `公式编号格式` | `附录公式编号格式：（附{c}-{n}）` | 只在稿件有附录时才有意义（附录里 `{c}` 取标题里的标识） |
| 脚注（可写可不写） | `脚注：<段落属性>` | `脚注：宋体/Times New Roman 小五 不加粗 不倾斜 左对齐 行距1.0倍 段前0磅 段后0磅 首行缩进0字符` | 写一半（`脚注：宋体 小五`）——声明了就得字段齐备 |

**页眉页脚可用的域**（封闭集合，写别的直接报错）：`{页码}`、`{总页数}`、
`{样式标题:<Word 样式名>}`（如 `{样式标题:Heading 1}` = 当前章标题）。域的值由 Word 计算，
打开或打印预览时更新。

### 3.2 几条容易写错的硬性规则

- **单位分工**：字号用 `pt`，行距 / 段前 / 段后 / 边框粗 / 线宽用 `磅`。写反会报错并给出应写形式。
- **缩进是每个样式行的必填字段**，判据不是「这个样式需不需要缩进」，而是「不写会不会悄悄继承」：
  正文写了 `首行缩进2字符` 之后 `Normal` 就带上了它，凡基于 `Normal` 又没自己声明的样式都会跟着缩进。
  图片段落、表内文字这类被顶右再叠加居中会**顶出右边界**。
- **`图` 与 `图片题注` 是两个样式**：`图` 是图片所在的段落（对齐由它的样式行控制），`图片题注`
  是题注文字。`图` 不写缩进会被顶右，看上去像"图片没居中"。
- **`紧凑` 只管表格里的段落**；**列表项走 `正文`**，不跟着 `紧凑` 走（否则每一项会被逐行居中）。
- **目录条目样式是生效的**：更新目录后字体缩进都保留；点线与页码由目录自己生成，`点线制表位` 对目录条目无效。
- **首行缩进与悬挂缩进互斥**：一行里都写只有一个生效，生成器直接报错。
- **线宽不写就用该边框样式的内置默认值**；1/4 磅是 Word 最细的单实线。
- **开了奇偶页不同 / 首页不同后，没显式写的那几套容器是「空白」而不是「继承默认」**：只写
  `页脚内容：{页码}` 再写 `偶数页页眉内容：…`，偶数页会整页没有页码。生成时会自动补齐空缺槽位并提示。

### 3.3 获取格式文件的四种方式

| 手上有什么 | 怎么做 |
|:--|:--|
| 空目录，先想看到成品 | `md-to-word init` 生成一份完整预设的 `format.txt` 和一份能直接导出的 `hello.md`，再照着改 |
| 参考 `.docx` 模板 | `md-to-word-template 参考.docx -o format.txt` 反推草稿，**能读出但表达不了的项列在末尾**；手调的直接格式读不到，需对照原文件逐项核对 |
| 文字或口头的格式说明 | 用户明文指定的部分照填，未提及的同套必填字段按 §3.5 推导补齐 |
| 什么都没提 | 直接用内置预设，先导一版标准 `.docx` 交付，再按反馈微调 |

内置预设：`zh-academic`（中文默认）、`zh-tw-academic`（繁中：PMingLiU + 微软正黑体 + `zh-TW` +
标点不压缩）、`zh-report`（技术报告）、`zh-gb9704`（GB/T 9704-2012 公文正文：A4、3 号仿宋、每页
22 行；不含红头/版记，需要时用 `--base-template` 保留）、`en-nature`（其他语种默认）、
`en-apa-student`（APA 7 学生论文）。不传 `--preset` 时的默认只由稿件语种决定，与 `--lang` 无关。

### 3.4 样式名（封闭词表）

`文档标题` `副标题` `作者` `日期` `摘要` `摘要标题` `关键词` `一级标题` `二级标题` `三级标题`
`四级标题` `五级标题` `六级标题` `正文` `首段` `普通` `紧凑` `表格题注` `表注` `图` `图片题注`
`参考文献` `参考文献标题` `引用块` `页眉` `页脚` `脚注` `代码` `目录标题` `目录一级` `目录二级`
`目录三级` `目录四级` `目录五级`

- **别名**（两者等价，可任选其一）：`论文标题` = `文档标题`，`表名` / `表题` = `表格题注`，`图名` / `图题` = `图片题注`。
  除这五个之外没有同义词，表外的名字一律报错。
- 每个属性与样式名都有英文正典写法，可与中文混写（`Title:`、`Body Text:`、`bold`、`not-italic`、
  `justify`、`line-spacing 1.5`、`space-before 0pt`、`indent 0`），示例见内置预设 `en-nature.txt`。
  否定式必须带连字符：`not-bold`、`not-italic`。报错文案跟随输入语言。
- **无条件必填**：`文档标题`、`一级标题`、`正文`、`首段`、`普通`。
- **用到才必填**：二~六级标题按稿件实际层级；表格 `表格`+`表头`+`紧凑`；图片 `图`+`图片题注`；
  目录 `目录标题`+`目录一/二/三级`（四级五级可选但要连着写）；摘要 `摘要标题`+`摘要`；参考文献
  `参考文献标题`+`参考文献`（用 `.bib` 时）；引用块 `引用块`；`页眉内容` 必配 `页眉`（页脚同理，按节的页眉页脚内容一样算）。
- **联动必填**：只有当格式文件**声明了目录样式**时，已声明的 `摘要标题` / `参考文献标题` 须显式写 `加入目录` 或 `不入目录`；
  只有当页眉写了 **`{样式标题:Heading ...}`** 时，已声明的 `摘要标题` / `参考文献标题` 须显式写 `加入页眉` 或 `不入页眉`。
  两者都未用的普通报告完全免写。

### 3.5 用户只提了一部分时怎么推

1. **明文优先**：用户或期刊写明的一律照填。
2. **学科体系兜底**：没写明时按学科借权威规范（英文社科 APA 7th、工程 IEEE、中文 GB/T 7714）。
3. **以正文为基准相对推导**：数据与注释（`紧凑`/表注/代码/脚注）比正文小一档，行距收敛到单倍，
   段前后 0 磅；题注比正文小 1 磅或同号加粗；一级标题比正文大 2~3 磅，文档标题大 4~6 磅。

具体取值不用另立一张表：内置预设就是默认值的唯一真相源。

## 4. 参考文献（`.bib` / CSL-JSON）

文献列表由引擎生成，作者只提供文献库与正文里的引用 key。工作顺序见 `--guide`；没有明确格式要求
时直接用内置预设，先交一版合规 `.docx`，再按反馈微调。

- **无参考文献**：YAML 不写 `bibliography:` 与 `csl:`，正文不出现 `[@key]`。
- **有参考文献**：YAML 写 `bibliography: refs.bib` 与 `csl: <样式>.csl`。文献列表由引擎生成，
  用户**不写**列表、不写 `%% 参考文献`（会被预检拒绝），只在文献区标题那一行之后由引擎插入。
- **`bibliography:` 也接受 CSL-JSON**（Zotero / Mendeley / Crossref 直接导出的 `.json`）：
  顶层是条目数组，或 `{"items": [...]}`；每条至少要有 `id`（正文 `[@id]` 靠它对应）。
  按**文件内容**判断，不看扩展名——`.json` 里放 BibTeX 也能读。JSON 写坏时预检报
  `gate.bib.json` 并指到文件；CSL-JSON 没有 `crossref` 继承这回事。
- **`.bib` 解析从宽**：BibTeX 的小语法错误（缺右括号、坏条目）可能被跳过，甚至吞掉
  后面的条目；它不会像 JSON 那样给 `gate.bib.json`。手写 `.bib` 请先用 BibTeX 工具
  检查一遍；Zotero 导出的 `.bib` 一般没这个问题。
- **手写文献列表不受支持**：只有手写条目时，先据此生成 `references.bib` 再引用。
- `csl:` 写内置文件名（如 `apa.csl`）时自动在包内查找；也可写相对稿件目录的路径或绝对路径。
  **自带 CSL 会自动规范化**：去掉 `<bibliography>` 上的 `hanging-indent` 与 `line-spacing` 并提示一行——
  直接格式优先级高于样式，不剥掉的话换个 CSL 悬挂缩进和行距就变了。
- **未实现的 CSL 构造会中止导出**：样式里出现本工具未实现的元素或属性时，预检会指出
  具体构造并报错，不会静默少印。当前硬边界包括 `class="note"`（脚注/ibid 类样式）、
  `institution`、`suppress-author`（样式级属性；正文的 `[-@key]` 不受影响）、
  `et-al-subsequent-*`、`gender` / `gender-form`、`display="indent"`、
  `givenname-disambiguation-rule="all-names"`，以及 `complete-all` 之外的
  `subsequent-author-substitute-rule`。内置 29 份样式均已通过这道检查。
- **数字制的序号成一栏**：引擎在 `[1]` 后补一个制表符，`参考文献` 写了 `悬挂缩进` 时正文从缩进处开始。
- **不写 `csl:` 时的默认**：中文稿按 GB/T 7714-2015 数字制，其他按 APA 7th（判据是 doc_lang：默认正文语种，格式文件可覆盖）。
  默认样式只有一处定义，不会因为换入口换出两种文献表。
- **正文引用写法**：

  | 写法 | 渲染 |
  |:--|:--|
  | `[@key]` | 括号引用；多篇 `[@a; @b]`，带页码 `[@a, p. 33]`（`[@a, 33]` 同义），带前缀 `[see @a]` |
  | `@key` | 叙述引用（`正如 @a 所指出`）；带页码 `@a [p. 33]` |
  | `[-@a]` | 只出年份：`[-@a]` → `(2020)`；可与完整引用同组写 `[@a; -@b]`，前缀写 `[see -@a]` |
  | `user@example.com` | 原样输出——`@` 前是 ASCII 字母或数字时不算引用（汉字不算，中文里写「见@eq-1」是引用） |

- **对不上的 key 会被导前预检拦下**：正文引了 `.bib` 里没有的 key，或 YAML 漏写 `bibliography:`，
  都在导出前报错并指到行号。

## 5. 导出与门禁

### 5.1 一条命令做完六件事

```
导前预检 → 生成样式模板 → 读成文档模型 → 写出 docx → 防丢内容检查 → 产物与格式要求逐条对账
```

样式模板每次导出实时生成，不落盘复用；**样式**只有一个来源，就是格式文件。

只想先确认稿件能不能过门禁：`md-to-word 稿件.md --validate-only`。它走同一套格式选择、预检与**完整试导出**：退出码 `0` 表示稿件与格式都能导出、`1` 带行号报错。
试导出只写临时目录（样式模板与 `.docx` 都在那里生成后删除），不写目标 `.docx`；输出目录是否
存在、是否可写，要到真正写文件时才知道。CI 与 Agent 可配
`--json`。

导出失败（预检、写出、对账任一处）不会留下写了一半的 `.docx`：产物先写进同目录的临时文件，
全部通过才换到目标文件名。如果目标位置本来就有上一次的成品，它不会被改动；结果里会明确提醒
那份是旧的（`--json` 的 `warnings`，code 为 `pipeline.stale_output`），别拿错。

防丢内容检查比三样：原稿里的每一个数字串、每一个汉字、每一个英文/拉丁词。少了就报错并
指出缺的是哪个，`--no-postflight` 可跳过。它按词频比对，只查「少」不查「多」；目录、题注
编号、文献表这些引擎生成的内容不参与比对。它不保证顺序、位置与排版，也不检查 `.bib` 文献库
本身与页眉页脚——超出这三类的丢失仍需抽查。这是该检查的边界，不当成「全文完整性」承诺。

拿到机构、高校或期刊下发的 `.docx` 时有两条路：

- **只要它的样式**：把格式读成格式文件，再照常导出（下面这段）。
- **要连它的封面一起保留**：那份 `.docx` 当底模，`--base-template` 把正文灌进去。
  样式仍然来自格式文件，底模只贡献前置件与全局文档设置。做法见 §9.3。

```
md-to-word-template 参考模板.docx -o format.txt   # 反推草稿，逐条核对
md-to-word 论文.md -f format.txt -o 论文.docx
```

反推只读格式数据：纸张、页边距、装订线、对称页边距、标点压缩、页眉页脚距边界、页码格式、文档网格、
校对语言、页眉页脚文字与域、表格（按文档里表格**实际引用**的样式读，不必叫 Table）、各样式的字体
字号行距段距缩进对齐。导出仍由本工具生成模板；多节模板（封面、目录、正文）同样适用，节的分界在
正文里用 `{{< section >}}` 标记。

属性按**生效值**读：样式自己没写的，沿 `basedOn` 链和 `docDefaults` 找，所以「派生样式的属性
写在基础样式上」这种最常见的写法读得出来，不会落成空值或默认值。

**反推的边界**——分两种，都不猜值填空。反推读的是**样式表**：段落上手调的直接格式检测不到，草稿里不会有提示，只能拿原文件核对；能检测到的其余问题与格式文件表达不了的项，会列在草稿末尾：

- **读不出来**：参考文件靠**段落直接格式**表达的东西（手敲的行距、手动的缩进、句子里单独加粗），
  以及没挂样式的表格。本工具读的是样式表，这一层读不到。
- **读得出来、但格式文件表达不了**：下边框以外的边框（上/左/右边框、方框）、底纹（段落底色、
  表头灰底、灰底字）、页眉页脚里的图片与图形（学校 logo、横线）。这些会按文档汇总成一条，
  列出是哪几个样式用的，导出后要在 Word 里补。

**不反推本工具的成品**：导出的 `.docx` 或灌过底模的产物带 `customXml/mdw_meta.xml`
（`kind="product"`），反推器会直接拒绝——成品里的样式是我们自己写进去的，底模里有同名
`Heading 1` 时还会读错那一条。请沿用导出时的 `format.txt`，或换学校/期刊下发的原始模板。

页眉页脚按**引用**取（各节写法不同时取正文节并提示），不会把三个章名当成三种页眉。
所以反推出来的是**草稿**：草稿末尾列出需人工确认的项，逐条核对后再用，不要直接拿去排版。

### 5.2 预检分两级，判据是「错了看不看得见」

| 级别 | 判据 | 例子 |
|:--|:--|:--|
| **阻断** | 静默出错，事后看不出来 | 内容丢字（表格列数不符）、退化成字面文本（`\tag{}`、未定义交叉引用）、格式不生效（样式名不在模板里、格式文件漏写表格样式）、YAML 里写了摘要关键词、题注写进图片方括号 |
| **提醒** | 看得见，只是不合规 | 图片宽度超版心（会被钳）、题注离图表远了、标题跳级、分节后多写分页、折行段落、词内星号按字面印出 |

提醒不阻断导出：作者可能有意为之，也可能打算在 Word 里收尾。若设为阻断，使用者只能以 `--no-check`
绕过，连真正的阻断项也会一并关闭。另有 `--no-postflight`（防丢内容）与 `--no-audit`（逐条对账）两个同类
开关，三个都只为排查工具本身，交付时不要用。

同一类提醒**合并成一条**输出，最多列 8 个行号、其余报数量，不按处刷屏；提醒同时进 `--json` 的 `messages`，
技能与脚本据此转述。

### 5.3 交付前必须肉眼核对

命令返回 `0` 只说明结构、样式与数量都过了闸门，**版面仍须在 Word 中人工核验**：表格行高列宽按内容
自适应、公式与题注的落版、页眉页脚只有真打开才能确认。导出末尾会输出这一条提醒。

**含动态域（目录、`{样式标题}` 页眉、跨节页码）或复杂宽表时，正式交付前开一次 `--pdf`**——这是唯一
能把域真正展开、看到真实分页的方式：

```bash
md-to-word 稿件.md -o 输出.docx --pdf
```

拿到 PDF 后抽四处核对：首页 / 最宽表格页 / 公式密集页 / 参考文献页。不可用时（Windows、未装 Word、
或装了但从没启动过）自动跳过，不影响 `.docx` 产出（退出码 `3`）。

### 5.4 学位论文

封面、前置件、分节页码、按章编号、双线章名页眉这些只跟学位论文有关的部分，集中在 §9。
`--base-template` 那条路也在那里（§9.3）。

## 6. 能力边界

**支持**：样式行能声明的全部段落属性（字体、字号、加粗倾斜、样式级颜色、对齐、缩进、行距、段距、边框与
表格线宽、字符间距、分页控制）；纸张、装订线与对称页边距；校对语言与标点压缩；页眉页脚与三类域；
奇偶页/首页不同、分节页码；表格（三线表、全网格线、顶底线、无边框、跨页重复表头、单元格对齐与
内边距、列宽比例）；原生 OMML 公式与交叉引用；图与题注；`.bib` + CSL 文献；行内格式（加粗、斜体、
删除线、下划线、上下标、行内代码、链接）；三级列表与引用块内列表；脚注；以及通过 `--base-template`
保留已有 `.docx` 的封面/前置件（§9.3）。

**字体与打开环境**：`.docx` 只记录字体名，不嵌入字体；最终显示取决于**打开文件的机器**。
预设按中文 Windows + Microsoft Word 的常见字体声明（宋体/黑体/仿宋/楷体、Times New Roman；
zh-tw 的新細明體/微軟正黑體；公文的方正小标宋简体不是系统自带，需自行安装）。缺字体时 Word
会替换，分页与换行可能变，但文件里的字体声明不变；正式交付前在目标机器或 Word 里核对一次。
**验收目标是 Microsoft Word**：WPS 能打开 `.docx`，但目录不会自动展开，章名页眉可能显示
`Error! The style is not specified.`，不保证与 Word 一致；交付给用 WPS 的收件方时，请用 WPS 打开核对。

**先分清责任**：下面三张表分开列——本工具明确不做的、Word/格式本身的限制、可以配置的设计参数。
标成“Word”的不是本工具的缺陷，换工具也一样；标成“本工具不支持”的，写法上会保留原文或明确中止，不静默吞掉内容。

**需要组合三层**：整段/整类样式改字体、颜色、间距、对齐，由 `format.txt` 写样式属性（如 `颜色#1F4E79`），
MD 用 `#` 或 `%% 样式名` 命中；某几个字的局部加粗、斜体、上下标、下划线、等宽，直接在 MD 里写
`**加粗**`、`*斜体*`、`H~2~O`、`x^2^`、`[字]{.underline}`、`` `code` ``。定制图形封面、徽标、签署页、
下划线填空表：**有现成 `.docx` 模板时用 `--base-template` 保留前置页并灌入正文**（§9.3）；没有底模时，
简版文字封面可用 `%%` + `{{< section >}}`，复杂图形封面需导出后在 Word 合并。

**本工具明确不支持**：

| 需求 | 会怎样 |
|:--|:--|
| 行内局部改文字颜色（如某几个字标红） | 没有 `{color=…}` 行内语法；写了会**原样留在正文**，不会变色。要局部改色就在 Word 里改，或抽成独立段落样式 |
| 合并单元格、斜线表头、单元格底纹 | Markdown 表格只有规则二维网格，按网格导出；合并/斜线/底纹到 Word 里做 |
| 多栏混排、文字环绕的浮动图 | 单栏是唯一正文版式，图片走独立居中图段；双面印刷的 `对称页边距：开` 与 `装订线` 支持 |
| 任意制表位 | 格式文件只认 `点线制表位`（右对齐 + 点线引导）；其它制表位在 Word 里加 |
| 列表项里紧跟正文的围栏代码块（中间不空行） | 列表项只承载段落；导出会中止，并提示把代码块移出列表。中间空一行再缩进写，代码块会作为独立段落排在列表之后（不再属于该列表项） |
| 脚注里的公式 | 脚注只支持行内格式、链接与引文；公式会中止导出 |
| 引文与文献表的自动更新（Word 域 / Zotero 插件） | 引文与文献表在导出时写成文本，不是 Word 域；在 Word 里改稿不会自动更新，改完稿件重新导出。需要 Word 内实时更新请用 Zotero 插件 |
| 阿拉伯语、希伯来语等从右到左文字 | 按从左到右排版（不写段落 bidi）：内容不丢，但对齐与标点方向不符合 RTL 习惯；导出后在 Word 里设段落方向 |
| 某个样式同时声明「不入目录」和「加入页眉」 | 格式文件校验直接报错：两者物理互斥。改声明，或用 `{{< section >}}` 切节设置该节页眉 |

**Word / 格式本身的限制**（不是本工具能改的）：

| 会看到什么 | 原因 |
|:--|:--|
| 带编号公式里求和/积分的上下限排到右侧 | 带编号公式按行内公式排；内容与符号完整，只是排法不同 |
| 长公式超过版心 | Word 会在运算符处断行，编号可能无法保持右对齐；预检会提醒。建议拆成多条公式或缩短 |
| 行内公式含求和/积分/根号，所在行变高 | 行距是段落级属性，Word 不会为单个行内公式压缩；常见约 1.5 倍 |

**设计参数（可配置，不是缺陷）**：

| 参数 | 默认行为 | 怎么改 |
|:--|:--|:--|
| 表格单元格内边距 | 左右 0.19cm、上下 0（与 Word 的 Normal Table 一致） | 写 `单元格内边距Ncm` 改成四周同值；窄列会相应变窄 |
| 表格列宽 | 按分隔行 `---` 的段数比例分配 | 列多时每列会变窄，预检会提醒窄列；要留白就减少列数或加内边距 |
| 列表层级 | 最多三级，第四级起并入第三级 | 拆成新的三级列表，或降级为正文段落 |
| PDF 图 | 按 300 dpi 栅格化后嵌入 | 需要矢量图时本工具做不到；在导出后的 Word 里替换为矢量对象 |
| 图片宽度超过版心 | 钳成版心宽（A4 + 2.54cm 边距下 15.92cm，有装订线再减它） | 导出前把 `width=` 改小，或加宽版心 |

预检会按格式文件算出真实版心，绝对宽度超限或百分比超过 100% 时出一条提醒（不阻断导出）。

**CSL 的已知差异（不是硬边界）**：

| 会看到什么 | 怎么办 |
|:--|:--|
| 中文著者-出版年文献表按文种分组（中文、日文、西文、俄文、其他），组内按字符编码排序，不按拼音（实测顺序：吴、周、张、王、赵、陈） | 需要拼音/笔画顺序时在 Word 里调整，或改用数字制。CSL 本身没有规定拼音排序；这是本引擎的排序口径，不是“实现不了”的边界 |
| 样式的 `left-margin` / `right-inline` 用于数字制的序号栏；其他排法会按流水排 | 需要不同的栏位排法时在 Word 里调，或改样式 |

叙述式引用的语法只接受**单个 `@key`**（`@a [p. 33]`）；`[@a; @b]` 是括号式多篇引用，
不是叙述式，这是语法定义，不是降级或边界。

**逐条语言**：中文条目印「等」、西文条目印「et al.」，同一份文献表里各按各的。语言先取文献的
`language` / `langid`（CSL-JSON 的 `language`）；没写时按题名的文字判断（其次看作者）：汉字为中文、
假名为日文、西里尔字母为俄文，拉丁字母按英文处理。中文期刊常给英文题名，这类条目请在 `.bib`
里显式写 `language = {chinese}`，否则会被当成西文条目。

**「逐字节一致」的口径**：同一平台上，同一份源重复导出逐字节相同——时间戳、权限、条目顺序、
zip 的平台标识都已钉死。换平台不算：deflate 压缩流的字节取决于 zlib 的实现与版本，macOS 的系统
zlib 与 Windows 上 CPython 自带那份打出来内容一致、字节不同。跨机器核对请看解包后的内容。

## 8. 报错速查

**文案跟随稿件语种**：中文稿读中文报错，英文稿读英文报错（含方括号里的类别标签与样式名举例）。
方括号标签是稳定的类别标识，便于对照下表；括号里的具体说明给出该改哪一行。

| 现象 | 原因与处置 |
|:--|:--|
| `[结构样式缺失]` | 稿件用到了某结构，格式文件没声明对应样式行。按报错给的行号补那一行，或换用预设 |
| `[段落样式]` | `%%` 后面的名字不在 §3.4 词表里，核对写法 |
| 格式文件解析失败 | 属性词不在 §3.1 词表里；报错会给行号、原词与应写形式 |
| 图片没居中 | `图：` 样式行没写缩进，继承了正文的首行缩进 |
| 中文全篇标红波浪线 | 格式文件没写 `校对语言：zh-CN`（或繁体中文 `校对语言：zh-TW`） |
| 公式报「丢了字符」或「结构不完整」 | 花括号不配对（`\frac{a}{b`）最常见；按报错行号补全。字符与间距的增减都会被拦下，不会静默出稿 |
| 参考文献没生成 | YAML 缺 `bibliography:`、正文没有 `[@key]`、或没写文献区标题行 |
| 目录条目字体不对 | 目录条目样式没写成 Word 内置样式（`目录一/二/三级`），或写了 `点线制表位`（无效） |
| 页眉显示「错误!未找到引用源」 | `{样式标题:X}` 里的 X 不是 Word 样式名（应写 `Heading 1`） |
| 字体看起来对、Word 里却不是 | 参考模板的主题属性覆盖了显式字体；反推后由生成器剥离 `asciiTheme`/`eastAsiaTheme`/`themeColor`/`themeFill` 等 |
| 同一份稿子两次导出不一致 | 同平台不应发生，出现即报缺陷；跨平台字节不同不算缺陷（§6 末尾） |

## 9. 学位论文

### 9.1 学位论文比期刊论文多了什么

封面、原创性声明与英文封面见 §9.2–§9.3；前置件小写罗马页码、正文从 1 起见 §9.4（写法在 §2.5）；
目录与双线章名页眉见 §2.5，进目录的判据见 §9.7；公式按章编号与附录编号见 §2.3、§9.5；
GB/T 7714 见 §4；三线表与表头跨页重复见 §2.4、§3.1。

### 9.2 封面与前置件

封面不是一页，通常是一组：中文封面、英文封面、原创性声明、版权授权书，中间还夹空白页。
它们**都是版式**，`format.txt` 表达不了——md 能给居中、字号、段前段后、图片，给不了绝对定位、
文本框、固定行高下的精确对齐。

三条路，按能保证的程度排：

1. **灌进已有模板（`--base-template`，推荐）**：把高校、期刊或机构下发的那份 `.docx` 当前置件，正文换成我们排的。见 §9.3。
2. **纯文字封面**：若封面只有文字与简单图片、没有校徽定位框线，可直接用 Markdown 排（`%%` 样式行 + 图片 + 一个声明为「前置」的 `{{< section 前置 >}}` 收尾，页眉页脚由格式文件里这个名字决定），提前确认对方规范是否允许。
3. **导出后在 Word 里合并**：工具只产正文，封面另做再合并。最稳，但要手工。
   **不要用复制粘贴把已有封面粘进产物**——同名的样式会被 Word 重定义，整篇正文随之变形。

### 9.3 把正文灌进已有封面模板（`--base-template`）

```bash
md-to-word 稿件.md -f format.txt --base-template 底模.docx --keep-until 作者签名 -o 输出.docx
```

`--keep-until 某段文字`：以这段文字所在的段落为**最后一行**（含这一段），在它之后插入分节符，
之后的内容全部丢弃。单节和多节底模同一条规则；要保留整节，改用 `--cover-sections N`。
想留整页，就写这一页的最后一行（如「作者签名」或日期）。找不到、命中多处、或切点落在目录
之后都会直接拒绝。切点必须是**正文段落**：封面若是表格，表格里的文字不能当切点（分节符不能
插进单元格），请换成表格之后的一段文字，或先在 Word 里把封面分成独立一节。

**目录不保留**：底模里有目录（域或手工排的都算）时，切点必须停在它之前——目录由稿件写
`{{< toc >}}` 生成。切深了直接拒绝。

底模贡献：前置件那几节（连它自己的页面设置、页眉页脚、页码格式）、主题与默认字体字号、以及我们没声明的样式。正文的纸张、页边距、装订线、页码格式、镜像边距、标点压缩、校对语言和声明过的样式来自格式文件。

文档级设置只有一份：`对称页边距`、`标点压缩`、奇偶页页眉/页脚和 Word 兼容模式必须与底模一致；不一致时直接拒绝，不替用户改封面，也不为了多支持模板做特殊兼容。请改格式文件或换一份底模。兼容模式不一致时，用 Word 打开底模，走「文件 > 信息 > 转换」（普通保存不会升级）；转换可能重排封面，转换后请重新检查切点。校对语言跟格式或稿件语言（只影响拼写检查）；主题与默认字体字号仍跟底模，表格单元格、空段落这类没有显式样式的段落可能略有出入。

**正文分页不保证逐页一致**：前置件结构逐节点保留，正文内容、样式和页面设置一致；但 Word 对分节后的首段有 space-before 处理差异，正文分页可能与单独导出不同。导出会在装了 Word 的机器上逐页验封面；正文请在 Word 里过一眼。

**验不过就不产出文件**。结构验真跨平台跑：前置件逐节点一致、原件的样式编号主题一样没少、
正文引用的样式都存在。版面验真在装了 Word 的机器上做：原件和产物各排一次版，逐页逐词比坐标，
差一点就删掉产物。Windows 上只跑第一层，导出会说清楚。底模带批注或修订标记时，这些标记会改变 Word 的排版占位，逐页比对不可靠，工具会跳过版面验真并提示人工核对。

它验不了两件事：切点选得对不对（导出会警告「切点之后的内容不会保留」，并列出第一段），以及封面里的域、宏按钮
打开时要不要点一下。切点在段落上，不在页面上——页只有 Word 排完版才存在；
想留整页，就写这一页的最后一行。

**盲审提交**：底模的 `docProps/` 会原样跟着成品走——作者、单位、自定义属性（学号）、封面缩略图、
批注（含内容）都可能在里面。加 `--blind-review` 在发布前清掉这些文件属性（core/app、自定义属性、缩略图、
批注（含内容）与修订作者）；不开这个开关时，底模带身份会在导出结果里提醒。它只清文件元数据：正文、封面文字
与页眉里的姓名不会被替换，仍需作者自己处理。

### 9.4 分节与页码

**一条规矩**：分节标记给**它下面那一节**命名，这个节名的页码、页眉、页脚在格式文件里声明。
所以「前置件小写罗马」不是写在稿件里，而是格式文件里的三行：

```
分节：前置
前置页码：小写罗马 起始1
前置页脚内容：{页码}
```

稿件在目录之后、第一章之前写 `{{< section 正文 >}}`，它收尾的正是前置件。

- 封面单独一节时，在封面内容之后写 `{{< section 前置 >}}`，并让「前置」这一节不要页眉；
  封面不显示页码就用 `分节：封面` ＋「封面页脚内容：无」。
- 节名在 `zh-academic` 与 `zh-tw-academic` 里已经声明好（封面 / 前置 / 正文 / 附录）；自己的格式文件里角色名随意取，
  每个名字先写一行「分节：名字」。
- 分节符自带「下一页」，**后面不要再写 `{{< pagebreak >}}`**，叠加会多顶出一页（预检会提醒）。

### 9.5 公式按章、按附录编号

- 按章：YAML 里 `crossref:` 换行缩进 `chapters: true`（**不能写成一行**），章号取公式所属一级标题的
  序号，不读标题里手写的数字。
- 附录：`# 附录A 实验数据` 这类一级标题按附录章处理，`{c}` 取 A，附录内的序号从 1 起；
  标题没写标识时按出现顺序给 A、B、C。附录**不占正文章号**——附录前的六章仍是 1~6，后面的「致谢」
  接着是第 7 章。
- 学校要「（附2-1）」这种前缀，写一行 `附录公式编号格式：（附{c}-{n}）`；不写就沿用正文那套。

### 9.6 双线章名页眉

格式文件写 `页眉内容：{样式标题:Heading 1}`，页眉就跟着每章的标题走。两件事必须同时成立：

- 稿件里每章都用 `#`（一级标题），写 `##` 就取不到；
- `参考文献标题`（或 `摘要标题`）须显式声明 `加入目录 加入页眉`（若不想入页眉则写 `不入页眉`），否则参考文献那几页的页眉还停在前一章；未接入 `Heading 1` 的 `{.unlisted}` 标题同样不会切换页眉（需要时用 `{{< section >}}`）。

### 9.7 常见问题

下表这些情况不会报错，只会让结果不对：

| 现象 | 原因 |
|:--|:--|
| 表格设了居中却靠左 | 分隔行写了冒号才是「每列表态」，整表对齐由 `紧凑：` 那行的对齐决定 |
| 行内公式把所在行撑高或压住 | 行内公式参与正文段落行距；固定行距（`行距20磅`）下超高部分会被裁切，改用 `行距最小值` 或加大行距 |
