## 1. 样式映射与边界

### 1.1 样式映射表

> **Quarto 与 Pandoc 的关系**：Quarto 内嵌 Pandoc，docx 输出正是走 Pandoc 的 docx writer 与样式匹配逻辑。因此下文 "Pandoc 样式映射 / 转换规则" 指的就是这一底层行为，Quarto 导出同样适用，两者不冲突。

Pandoc 在 reference.docx 中识别的样式名是固定的，不能擅自改名：

| Pandoc 样式名 | 用途 | python-docx 访问方式 |
|---|---|---|
| Title | 文档/论文大标题 | `doc.styles['Title']` |
| Abstract | 摘要 | `doc.styles['Abstract']` |
| First Paragraph | 章节首段 | `doc.styles['First Paragraph']` |
| Body Text | 正文 | `doc.styles['Body Text']` |
| Normal | 其余样式的**继承源头**（段落不直接用它；列表项走 `Compact`） | `doc.styles['Normal']` |
| Compact | 紧凑正文 | `doc.styles['Compact']` |
| Heading 1—9 | 标题 | `doc.styles['Heading X']` |
| Table Caption | 表名 | `doc.styles['Table Caption']` |
| Image Caption | 图名 | `doc.styles['Image Caption']` |
| Captioned Figure | 图片段落（原生图语法 `![caption](path)` 时生成，模板已设居中） | `doc.styles['Captioned Figure']` |
| Table Note | 表注 | `doc.styles['Table Note']` |
| Bibliography | 参考文献 | `doc.styles['Bibliography']` – 用 `::: {#refs}` 控制位置 |
| References Title | 参考文献标题（自定义样式）| `doc.styles['References Title']` – 与 `::: {#refs}` div 配合控制标题样式 |
| Keywords | 关键词 | `doc.styles['Keywords']` |
| Footnote Text | 脚注正文 | `doc.styles['Footnote Text']` |
| Footnote Reference | 脚注序号（字符样式，上标）| `doc.styles['Footnote Reference']` |
| Table | 表格边框 | `doc.styles['Table']` |

> **Pandoc 样式匹配规则**：按**样式名**或**styleId**匹配 `custom-style="X"`（「Table Note」「TableNote」都认）。两者都不存在时，Pandoc 会**静默**建一个空壳样式（继承 Normal/Body Text）——格式不生效且没有警告，`check_md.py` 能在导出前检出。

> `Keywords`、`Table Note` 这类样式**已预置在底模里**——Pandoc 自带的参考文档没有它们，
> 不预置就会静默建出空壳样式（继承 `Normal` 的格式，看不出对错）。

### 1.2 多套正文样式的说明

Pandoc 内部使用启发式规则将不同段落映射到不同样式：

| 落在这一样式的东西（实测） | 映射为 |
|---|---|
| 紧跟标题之后的**第一个段落** | `First Paragraph` |
| 其余正文段落（**与长短无关**） | `Body Text` |
| **列表项**（无序与有序都是） | `Compact` |
| **表格内所有段落**（含表头） | `Compact` |
| 引用块 `>` | `Block Text` |
| 脚注文字 `[^1]: …` | `Footnote Text` |
| 脚注序号 `[^1]` | `Footnote Reference` |
| 紧跟列表之后的段落 | `First Paragraph` |

**怎么设**：「正文」与「首段」设为相同格式（标题后的第一段就与其余段落一致）；「紧凑」有表格/列表才需要（通常比正文小 1.5~2 磅、不缩进、段前后 0）；「普通」是其余样式的继承源头，**必须显式声明**，否则底模默认值会传给所有基于它的样式。

### 1.3 中文字体处理

在 OOXML 中，中文字体（东亚字体）和西文字体是独立设置的。`generate_template.py` 的分离逻辑：

| 写法 | 效果 |
|------|------|
| `宋体/Times New Roman` | eastAsia=宋体，ascii/hAnsi=Times New Roman |
| `宋体` | 只设 eastAsia，Latin 用全局默认 |
| `Times New Roman` | 只设 ascii/hAnsi，东亚不动 |
| `西文字体：Times New Roman` | 全局西文默认，未单独指定 Latin 的样式都使用 |

### 1.4 能力边界

**完全支持**：
- **样式行能声明的属性**：字体（中西文自动分离）、字号、加粗/倾斜、对齐、缩进、行距、段间距、
  边框与表格线宽、全局西文字体——唯一写法见 §1.5 速查表。
- **行内格式（写在正文里就行，不经过模板）**：`**加粗**`、`*斜体*`、`~~删除线~~`、`[下划线]{.underline}`、`H~2~O` 下标、`x^2^` 上标——渲染器直接把这些写成字符属性，与样式级设置互不干扰（样式写「不加粗」时，正文里 `**加粗**` 那几个字照样加粗）
- **页眉 / 页脚 / 页码**（含奇偶页不同、首页不同、起始页码、`{页码}` `{总页数}` `{样式标题:X}` 三种域）
- **表格内各行格式**（表头行单独字体字号加粗、跨页重复标题行、单元格垂直对齐、三线表线宽可调）
- **脚注**（正文里写 `[^1]` + `[^1]: 注释文字`）——样式行 `脚注：` 怎么写见 §1.5
- **字符间距**（样式行写 `字距0.5磅` 加宽、`字距-0.2磅` 紧缩）
- 公式交叉引用（`{#eq-xxx}` + `@eq-xxx`，中文前缀由 YAML `crossref:` 决定）

> ⚠ **图片不要加 `{#fig-xxx}` 标签**。加了 Quarto 会为「图 + 题注」生成一个单格表格以保持同页，
> 而该表格走「表格：」那行声明的 `Table` 样式（实测 `w:tblStyle w:val="Table"`），图片上下
> 因此被套上三线表的框线；图片段落也同时失去 `CaptionedFigure`，不再居中。
> 图号一律**手写在题注文字里**（`**图 1** …`），表格题注走 `::: {custom-style="Table Caption"}`。
> 本技能只支持公式的交叉引用（`{#eq-x}` + `@eq-x`）。

**多节的页码切换**（如前置罗马 → 正文阿拉伯）：用正文里的 `{{< section >}}` 标记做，
见 §1.9；参考模板本身仍须**单节**（pandoc 只取第一个 `sectPr`）。

**不支持**（需在 Word 中手动调整或合并）：
- 定制花式封面页（含单位徽标 Logo、下划线填空表单、绝对定位框等；YAML `title:` 仅生成正文开篇标准大标题，定制封面建议在 Word 中合并到首页）
- 跨行/跨列合并单元格（rowspan/colspan）与斜线表头（Markdown 表格仅支持规则二维网格）
- 任意制表位（`点线制表位` 是唯一的例外：给**非目录样式**加一条右对齐的点线引导。目录条目上那条点线是 Word 更新域时自己画的，与本设置无关——见 §1.5）。**编号列表与项目符号是支持的**——Markdown 的 `- ` / `1. ` 直接可用
- 底纹 / 背景色
- 脚注的位置（固定印在引用它的那一页底部，Word 的版面规则）
> 换行与分页的控制共四种，都写在样式行里：`与下段同页`、`段前分页`、`段中不分页`、`孤行控制`/`取消孤行控制`（Word 里**孤行控制默认是开的**，故 `孤行控制` 通常只是个显式保险）；表头另有 `跨页重复`。

> ⚠ **图片宽度上限 = 版心宽**：写超了**会被静默钳成版心宽**——不报错、也没有警告。
> A4 + 2.54cm 边距下版心是 15.92cm（有装订线再减它），实测写 `{width=25cm}` 拿到 15.92cm。
> 钳制用的是 `pgSz - pgMar` 那条公式（`design.md §1.5`），所以**它减装订线**这点要留意。
> 导前预检会按要求文件算出真实版心并拦下超宽的写法。
- 分栏排版与图片文字环绕
- 字体颜色（模板统一强制黑色，不能要求彩色文字）

### 1.5 requirements.txt 写法速查表（唯一写法）

> **设计原则**：每个属性只有一种规范写法（同义词已收敛）。照表填写即可；**表外的词一律报错**
> ——解析是整词消费：认不出的词会被指出（带行号）并给出应写形式，既不静默丢弃、也不会被别的规则读错。
>
> **与 `SKILL.md §2.1` 的分工**：那份**每次都会加载**，放的是「属性 → 唯一写法」的速查版，
> 够日常填表用；本表是**按需查阅**的详版，额外给出**错误写法对照**与逐条原理（为什么这样定）。

**样式行格式**：`<样式名>：<属性1> <属性2> …`（冒号用 `：` 或 `:`，属性间空格分隔）

| 属性 | 唯一写法 | 示例 | 错误写法（会被报错）|
|:--|:--|:--|:--|
| 字体 | `<中文字体>/<西文字体>` 或单字体 | `宋体/Times New Roman`、`Times New Roman` | — |
| 字号 | `<数字>pt` 或中文号数 | `12pt`、`小四`、`三号` | `12磅`、`12`（无单位）、`小四号`（号数末尾不带「号」）|
| 加粗 | `加粗` / `不加粗` | `加粗` | — |
| 倾斜 | `倾斜` / `不倾斜` | `倾斜` | `斜体`、`中等倾斜` |
| 对齐 | `居中` / `左对齐` / `右对齐` / `两端对齐` | `左对齐` | `靠左`、`靠右`、`分散对齐` |
| 行距（倍数）| `行距<数字>倍` | `行距1.25倍` | `1.5倍行距`、`单倍行距`、`双倍行距` |
| 行距（固定值）| `行距<数字>磅` | `行距20磅` | `行距固定20磅`、`行距固定值20磅`（死钉在 N 磅，内容比它高会被裁掉）|
| 行距（最小值）| `行距最小值<数字>磅` | `行距最小值25磅` | `最小行距25磅`——**当场报错**并提示应写形式 |
| 段前/段后 | `段前<数字>磅` `段后<数字>磅`（不需间距写 `段前0磅 段后0磅`）| `段前0磅 段后6磅` | — |
| 缩进（**必填，且每行只能写一种**）| `首行缩进<数字>字符`（中文）/ `首行缩进<数字>英寸`（英文）/ `悬挂缩进<数字>英寸` | `首行缩进2字符`、`首行缩进0字符`、`悬挂缩进0.5英寸` | `首行缩进1厘米`、`悬挂缩进2字符`、**同一行既写首行缩进又写悬挂缩进** |
| 左缩进 | `左缩进<数字>字符` | `左缩进2字符` | `缩进2字符`、`左缩进2厘米` |
| 点线制表位 | `点线制表位` | 手打的行行尾加 `点线制表位`（给行尾的页码之类做右对齐 + 点线引导）| 写位置数字（落在版心右边界，由纸张与页边距算出）；**写在 `目录一/二/三级` 上不生效**——那三行的定义会被 Word 更新域时重置，见 §1.5 |
| 段前分页 / 段中不分页 / 取消孤行控制 | 三个独立词，可叠用 | `一级标题：… 与下段同页 段前分页`；`段前分页` 比手写 `{{< pagebreak >}}` 稳——内容增删后仍自动从新页开始 |
| 加入目录 | `加入目录` | `摘要标题：… 加入目录` | 写在正文类样式（`正文`/`首段`/`普通`/`紧凑`）上——它给样式挂大纲级别，目录域按级别收集条目，挂正文上会让**每一段都变成目录条目** |
| 跨页重复 | `跨页重复` | `表头：… 跨页重复` | 写在 `表头：` 以外的样式行——它描述的是表头行（`w:tblHeader`），写在别处既不生效也不落进 XML |
| 与下段同页 | `与下段同页` | `目录标题：… 与下段同页` | — （题注跟着表/图、标题不落单页尾，都靠它；不写则完全取决于底模继承）|
| 无边框 | `无边框`（去除底模自带下边框，如文档标题）| 文档标题行尾加 `无边框` | `下边框无`——它与 `无边框` 产物**逐字节相同**（都清掉整段 `w:pBdr`），故只保留一种写法 |
| 下边框 | `下边框<单线\|双线>` `[边框粗<N>磅]` | `页眉：宋体/Times New Roman 小五 居中 行距1.0倍 段前0磅 段后0磅 首行缩进0字符 下边框双线` | 写 `下划线`（那是字符属性）；**`边框粗` 单独写**（没有下边框时它无处可落，实测产物里连 `w:pBdr` 都没有）|
| 表格宽度 | **不用声明**——默认完全不动：pandoc 与 Word 按内容排 | — | 想自己定列宽比例，把分隔行的短横线写得长短不一即可；规则、边界与实现见 `SKILL.md §一 3` 与 `design.md §1.12` |
| 表格（**含表格时必填**）| `表格：<居中\|左对齐\|右对齐> <三线表\|全网格线\|顶底线\|无边框> [线宽上/线宽底/线宽表头下<N>磅] [线宽内<N>磅（仅全网格线）] [单元格垂直居中\|顶端\|底端] [单元格内边距<N>cm]` | `表格：居中 三线表 线宽上1磅 线宽底1磅 线宽表头下0.25磅 单元格垂直居中 单元格内边距0.19cm` | `表格：居中 三线表(1磅)`；**三线表/顶底线写「线宽内」（没有内部横线，会报错）**；**无边框写任何线宽（不画线，会报错）**；**`单元格内边距` 单位用 cm 不用磅（`单元格内边距0.19磅` 会报错），不写即 0** |
| 表头行（**含表格时必填**）| `表头：<段落属性，同样式行语法> [跨页重复]` | `表头：宋体/Times New Roman 五号 加粗 居中 行距1.0倍 段前0磅 段后0磅 首行缩进0字符 跨页重复` | — |
| 页眉/页脚**样式** | `页眉：<段落属性，同样式行语法>` | `页眉：宋体/Times New Roman 小五 居中 行距1.0倍 段前0磅 段后0磅 首行缩进0字符` | 把内容写进样式行——字体段是**唯一的自由文本**，`页眉：某某大学 小五 居中 …`（字段齐备时）里的 `某某大学` 会被当成字体名**静默收下**，不报错 |
| 页眉/页脚**内容** | `页眉内容：` / `偶数页页眉内容：` / `首页页眉内容：` / `页脚内容：` / `偶数页页脚内容：` / `首页页脚内容：` | `页眉内容：{样式标题:Heading 1}` | `{样式标题:一级标题}`——STYLEREF 只认 **Word 样式名**（`Heading 1`），中文写法不是样式名。**生成期直接报错**；写「内容」行却不写对应的「样式行」（`页眉`/`页脚`）同样报错，判为「必填行缺失」|
| 脚注（可写可不写）| `脚注：<段落属性，同样式行语法>` | `脚注：宋体/Times New Roman 小五 不加粗 不倾斜 左对齐 行距1.0倍 段前0磅 段后0磅 首行缩进0字符` | 写一半（`脚注：宋体 小五`）——**声明了就得字段齐备**，缺字段会报错并列出缺哪些，生成中止 |
| 页码格式 | `页码：<阿拉伯\|罗马\|小写罗马\|字母\|大写字母> [起始<N>]` | `页码：阿拉伯 起始1` | `页码：1,2,3`；**写了它却没有 `{页码}` 域**——这一行只往 `sectPr` 写格式与起始值，页码要印出来得靠页眉/页脚内容里的 `{页码}` |
| 纸张 | `纸张：<A4\|Letter>`（不写默认 A4）| `纸张：A4` | `纸张：B5` |
| 装订线 | `装订线：<N>cm` | `装订线：1cm` | — （加在左边距之外；产物里是**折进左边距**写的，不写 `w:gutter`，理由见 `design.md §1.5`）|
| 文档网格 | `文档网格：每页<N>行` | `文档网格：每页22行` | — （只按行数指定，不支持「每行多少字」；行距倍数已自动补偿，不必手调）|
| 字符间距 | `字距<N>磅`（正数加宽、负数紧缩）| `字距0.5磅`、`字距-0.2磅` | `字间距0.5磅`（词序反了）|
| 页边距 | `页边距：上<数字>cm 下<数字>cm 左<数字>cm 右<数字>cm` | `页边距：上2.54cm 下2.54cm 左2.54cm 右2.54cm` | — |
| 页眉/页脚距边界 | `页眉距边界：<数字>cm` / `页脚距边界：<数字>cm` | `页眉距边界：1.40cm` | — |
| 西文字体 | `西文字体：<字体>`（全局默认西文）| `西文字体：Times New Roman` | — |
| 校对语言 | `校对语言：<语言代码>`（文档用什么语言写）| `校对语言：zh-CN` | `校对语言：中文` |

**样式名速查**：完整列表见 `SKILL.md §2.1`（那份每次全量加载，此处不再抄一遍）。

> ⚠ **`代码：` 可写可不写**：``` 围栏落 `SourceCode` 样式，底模已给它等宽字体（Consolas/宋体）、
> 清零缩进、单倍行距，所以不声明也是对的。行内 `` `code` `` 落 `VerbatimChar`，字体随之一致。

> ⚠ **脚注可以不写**：稿件里没有 `[^1]` 就用不上。但不写不等于不管——渲染器一定会给脚注打
> 样式标记，标记指不到定义就落到 `Normal`（正文那套：脚注与正文一样大、序号不上标）。
> 所以模板必定给这两个样式落定义：写了用写的，没写从正文推（字体对齐跟正文、字号降一档、
> 单倍行距、缩进 0），序号一律上标。

> ⚠ **目录：`目录标题` 生效，`目录一/二/三级` 不生效**。Word 更新目录域时会把重建的
> `toc 1/2/3` 空壳盖上去，我们写的字体、缩进、`点线制表位` 都被丢掉，条目按正文（Normal）排。
> **别向用户承诺能自定义目录条目的外观**；那三行写了无害，但改不动结果。
> （机制、实测数据与四条试过的补救路见 `design.md §2.23`。）
>
> `点线制表位` 在**非目录样式**上照常有效（给手打的行加一条右对齐点线引导）。
> 要让摘要这类标题进目录，仍是在它的样式行加 `加入目录`（**不能写在正文类样式上**——
> 它挂的是大纲级别，挂在正文上会让每一段都进目录）。

> ⚠ **非西文文档要写 `校对语言：`**（中文 zh-CN、日文 ja-JP）。不写就按底模的英文校对，
> Word 会把中文整篇标成拼写错误——标记只在编辑视图显示、不打印，但看着像文档到处是错。

> ⚠ **首行缩进与悬挂缩进互斥**：二者共用 OOXML `w:ind` 的同一组属性，一行里都写只有一个会生效。
> 生成器现在会直接报错（参考文献写「悬挂缩进0.5英寸」，不要再补「首行缩进0字符」）。

> ⚠ **缩进是每个契约样式的必填字段**。判据不是"这个样式需不需要缩进"，而是"不写会不会悄悄继承"：
> 正文写了「首行缩进2字符」之后 `Normal` 就带上了它，凡 `basedOn Normal` 又没自己声明 `w:ind`
> 的样式都会跟着缩进。图片段落、表内文字这类一行就结束的，被顶右再叠加居中会**顶出右边界**。
> 故不漏写的方式只有一个：每个样式行都显式写「首行缩进0字符」或实际的缩进值。

> ⚠ **单位分工**：字号用 `pt`（`12pt`），行距 / 段前 / 段后 / 边框粗 / 线宽用 `磅`。写反了会被报错并给出应写形式（`行距20pt`、`段前6pt`、`12磅` 都不认）。

> ⚠ **`图` 与 `图片题注` 是两个样式**，都要写。`图` 是**图片所在的那个段落**，`图片题注` 是图下的题注文字。
> `图` 不写缩进就会被顶右，看上去像"图片没居中"——实则是继承来的缩进。

> **线宽不写就用该边框样式的内置默认值**；**1/4 磅是 Word 最细的单实线**，再细会被自动夹到 0.25 磅。

**页眉/页脚内容里可用的域**（封闭集合，写别的直接报错）：

| 标记 | 渲染为 |
|:--|:--|
| `{页码}` | 当前页码（`PAGE` 域） |
| `{总页数}` | 全文页数（`NUMPAGES` 域） |
| `{样式标题:<样式名>}` | 该样式在本页或往前最近一处段落的文字（`STYLEREF` 域）。`{样式标题:Heading 1}` = 当前章标题，用于「页眉跟着章标题走」 |

> 域的值由 Word 计算：导出后用 Word 打开、打印预览或 Ctrl+A → F9 时更新。
> 若页眉显示「错误!未找到引用源」，是样式名没对上——生成模板时会把你在 requirements 里写的名字注册成样式别名，所以**写什么就用什么**，别中途改名。

> ⚠ **`紧凑` 管两处：表格里的所有段落 + Markdown 列表项**（实测：表内段落全部命中、列表项也全部命中，其余正文段落一律走「正文」）。表内文字的字体/字号/对齐/缩进**只能靠 `紧凑：` 这一行**控制；不写就继承正文的 2 字符首行缩进，表格里每格都会缩进。
> **若稿件同时有表格和列表**：两者共用这一条样式，按表格设的「居中 / 小五」会让列表也变成居中、小五。正式文档的正解是**不用 Markdown 列表**——条目写成行内序号（`（1）…`）作普通正文段落，把 `紧凑：` 留给表格。
> **表头行**无法用段落样式区分（表头和表体同为 `Compact`），只能靠 `表头：` 行走 Table 样式的条件格式。

> ⚠ **开了奇偶页不同 / 首页不同之后，没显式写的那几套容器是「空白」而不是「继承默认」**。例如只写「页脚内容：{页码}」再写「偶数页页眉内容：…」，偶数页会整页没有页码。生成模板时会把默认内容自动补进空缺槽位，并打印一行提示；要不同的内容就显式写 `偶数页页脚内容：`。


### 1.6 期刊未明确要求时的建议默认值与排版层级推导

> **平衡原则**：
> 1. **期刊明文优先**：期刊《Guide for Authors》或模板有明确要求的属性（如指定字体、双倍行距、单双栏），一律无条件遵从；
> 2. **学科体系兜底**：期刊未写明细节时，按学科借用权威规范（英文社科/管理学默认参考 APA 7th，工程参考 IEEE，中文参考 GB/T 7714）；
> 3. **基准相对推导**：未具细之处**绝不生搬硬套某条孤立绝对值**，而是以期刊正文字号（Base）为基准推导相对层级：
>    - **数据与注释（Compact/表注/代码/脚注）**：比正文小一档（小四→五号差 1.5pt；三号→小三只差 1pt），行距收敛到单倍（1.0~1.15 倍），段前后 0 磅（防撑爆版心）；
>    - **题注引导（表名/图名）**：比正文**小 1 磅**（或同号加粗），清晰区分于正文同时不压倒数据；
>    - **标题梯队**：一级标题比正文**大 2 ~ 3 磅**（加粗），论文大标题比正文**大 4 ~ 6 磅**（加粗居中）。

| 细节项 | 建议默认（以正文 12pt 为例） | 层级推导逻辑与说明 |
|:--|:--|:--|
| 行距 | 1.5 倍（`行距1.5倍`）| 通用投稿清稿折中；APA 双倍行距是审稿划线草稿惯例，期刊明文要求双倍才设双倍 |
| 正文字体/字号 | Times New Roman 12pt | 正文基准（Base）。若期刊要求 10.5pt，以下附属元素同步等比下调 |
| 正文对齐 | 两端对齐 | 现代期刊清稿版式通行；APA 审稿草稿的左对齐仅用于纸质批注 |
| 正文缩进 | 首行缩进 0.5 英寸（英文）/ 2 字符（中文）| 段落首行缩进；章节首段与摘要整段首行缩进 0 字符（不缩进，APA 惯例） |
| 摘要标题 | 居中、加粗 | 与正文同号或略大，居中呈现 |
| 一级标题 | 加粗、Base + 2pt（如 14pt） | 期刊未写时默认加粗，比正文略大 |
| 二级标题 | 倾斜、与 Base 同号（12pt） | 期刊未写时默认斜体 |
| 表名 / 图名 | 表上 / 图下，居中，Base - 1pt（如 11pt 加粗） | 略小于正文或同号加粗，形成视觉锚点 |
| 表内文字（紧凑） | 比正文小 1.5~2 磅（如 10pt/9pt），行距 1.0~1.15倍 | **数据密度高，必须紧凑**；不缩进、段前后 0 磅，防多列数据跨行撕裂 |
| 表注 | 表格下方、左对齐、Base - 1.5~2pt（如 10pt/10.5pt） | `*Note:*` 引导，说明口径与显著性水平 |
| 参考文献 | 两端对齐、悬挂缩进 0.5 英寸 | APA/国际通用标准 |
| 页眉 / 页码 | 不要求不加；要加居中/居右，小五号 | 页脚居中阿拉伯数字是最通行位置 |


### 1.7 公式编号

**只有一种写法**：`$$…$$ {#eq-xxx}`，编号由 Quarto crossref 生成。

```markdown
$$Y_{ij} = \alpha_0 + \beta_1 X_{1,ij} + \varepsilon_{ij}$$ {#eq-model1}
```

**顺序编号（默认）**：直接出 `(1)` `(2)`…，适合英文期刊全文连续编号。

**按章编号（中文学位论文）**：YAML 开 `crossref: chapters: true`，编号成为 `(5.1)`。

```yaml
crossref:
  chapters: true
```

- 章号取**公式所属一级标题的序号**，不读标题里手写的数字；标题按 1…N 顺序写时二者一致。
- **不要**开 `number-sections`：标题已有手写编号时它会再加一层，渲染成「1. 1 绪论」。

**正文里的引用标签（中文文档必看）**：`@eq-xxx` / `@fig-xxx` / `@tbl-xxx` 渲染出的前缀
默认是英文（`Equation 1` / `Figure 1` / `Table 1`），中文文档必须自己在 YAML 里改：

```yaml
crossref:
  eq-prefix: "式"
  fig-prefix: "图"
  tbl-prefix: "表"
```

不设的话会渲染成「如公式 Equation 1 所示」这种中英混排。三个前缀可单独设，只写要用的即可。

**编号外观**（导出加 `--eq-number-style`）：`asis`（默认）保持 `(5.1)`；`cjk` 改写成 `（5-1）`。

> ⚠ **不要写 `\tag{…}`**。它不是 Pandoc 语法：不报错，而是让整条公式退化成字面文本打进 Word。
> `check_md.py` 会拦下它并给出改写示例。编号靠右是后处理实现的，机制见 `design.md §1.3`。

### 1.8 稿件头部：哪些走 YAML、哪些必须包裹

| 头部元素 | 推荐写法 | 为什么不能全走 YAML |
|:--|:--|:--|
| 标题 | YAML `title:` | pandoc 原生映射 `Title` 样式 |
| 摘要 | `:::` 包裹 | YAML `abstract:` 虽能导出，但标题段由 pandoc 决定：默认英文 `Abstract`，`lang: zh-CN` 时标题段不出现，且无法精确控制摘要标题样式 |
| 关键词 | `:::` 包裹 | YAML 的 `keywords:` 在 docx 导出中会被直接丢弃，产物里不出现 |

标准头部写法：

```markdown
---
title: "标题"
---

::: {custom-style="Abstract Title"}
摘要
:::

::: {custom-style="Abstract"}
摘要正文……
:::

::: {custom-style="Keywords"}
关键词：甲；乙
:::
```

### 1.9 块级标记必须独占一行、并与正文隔空行

紧贴正文时 Pandoc 会把标记并进相邻段落，产物静默走形。**哪一侧要空行是不对称的**，
按标记各异（逐例渲染后核对产物段落得出，实现在 `skill_utils.block_marker_issues`）：

| 标记 | 与正文直接相邻会出事的一侧 | 后果 |
|:--|:--|:--|
| `$$…$$` 公式 | 后 | 后一行标题/正文被并进同一段（后处理重构公式表格时连带吞掉正文）|
| `{{< pagebreak >}}` | 后 | 同上 |
| `{{< toc >}}` / `{{< section … >}}` | 后 | 同上 |
| `![…](…)` 独占一行 | 前、后 | 前：并进上一段（样式跟着上一段走）；后：标题被并进图片段 |
| `:::` 围栏首行 | 前 | 整个围栏块退化成字面文本 |
| 表格首行 | 前 | 表格退化成字面文本 |
| 标题 / 围栏尾行 / 表格末行 | 无 | 两种粘法都无害，不检查 |

```markdown
前段正文。

$$Y = a + bX$$ {#eq-model1}

::: {custom-style="Keywords"}
关键词：甲；乙
:::

| 甲 | 乙 |
|---|---|
| 1 | 2 |

![图 1 描述](f.png){width=12cm}


{{< pagebreak >}}

# 2 章
```

- 三者都必须独占一行，写在句子中间不生效。
- `\newpage` / `\pagebreak` / `\clearpage` 在 docx 里不生效，分页一律用 `{{< pagebreak >}}`。
- **短代码只有三种**：`pagebreak` / `toc` / `section`。名字写错会被 Quarto 静默丢弃，
  故 `check_md.py` 把这份名单当封闭集合拦。

### 1.9.1 目录与分节：两个结构标记

> ⚠ **它们借用了 Quarto 的短代码写法，但不是 Quarto 短代码**：`{{< toc >}}` / `{{< section … >}}`
> 在 `quarto render` 看到它们**之前**就被本技能的 `expand_markers.py` 换成了原生 OOXML。
> 所以**在普通 Quarto 项目里单独用这两个写法是不生效的**（Quarto 只会当成不认识的 shortcode），
> 只有走本技能的 `export.sh` 才会被展开。搬到别处时别指望它照常工作。

这两个标记在**渲染前**被展开成 OOXML 块（`expand_markers.py`，接在预检之后、Quarto 之前；
机制见 `design.md §1.8.2`）。

```markdown
::: {custom-style="TOC Heading"}
目录
:::

{{< toc >}}

{{< section 页码=罗马 起始=1 >}}

# 1 绪论
```

**`{{< toc >}}` / `{{< toc 2 >}}`** —— 出目录域，位置就在这里。默认收 1–3 级（`\o "1-3"`），
带数字则指定到第几级。用**域**而不是 Pandoc `--toc` 的静态列表：条目页码要 Word 现算，
静态列表给不出页码。域在 Word 打开时自动更新一次；**页码要完全准确需再按一次 F9**——
域更新用的是展开前的分页，目录自己变长会把正文往后推。

进目录靠的是**大纲级别**：`#` 标题天然有，自定义样式的标题要在样式行写 `加入目录`（§1.5）；
目录标题样式基于 `Normal` 且不设大纲级别（不写 `加入目录`），故目录不收录自己。

**`{{< section … >}}`** —— 在此处收尾的**这一节**的分节符。参数描述的是**它结束的那一节**
（OOXML 里 sectPr 归属前一节），所以要写在「前置件」与「正文」之间，参数说的才是前置件：

| 参数 | 写法 | 说明 |
|:--|:--|:--|
| 页码 | `页码=罗马` | `阿拉伯`/`罗马`/`小写罗马`/`字母`/`大写字母`，与 requirements 的 `页码：` 同一套词 |
| 起始 | `起始=1` | 不写则接着上一节往下数 |

- **页面几何整段继承参考模板正文节**：纸张、页边距、分栏、文档网格都抄过来。
- **页脚照抄模板正文节的引用**（rId 从模板里读，不写死），所以页码域自动就有。
- **不引页眉引用**，故本节不排页眉（前置件通常如此）。参考模板只提供 default/even/first
  三个槽位；要给这一节另一套页眉得另建部件，不在本标记的能力内。
- 正文节的页码仍由 requirements 的 `页码：` 指令负责（走模板的 sectPr），标记只管前置节。

> ⚠ **严禁在 `{{< section >}}` 前后叠加 `{{< pagebreak >}}`**：分节符底层已自带下一页分页属性，叠加会导致多出一页空白页。普通单节文档（如商业报告、技术方案）通篇使用阿拉伯页码即可，无需使用此分节标记。

### 1.10 图表题注与表注规范（哪些包裹、哪些原生）

| 元素 | Markdown 语法形式 | 对应 Word 样式 | 机制与设计原因 |
|:-----|:------------------|:---------------|:---------------|
| **表格题注** | `::: {custom-style="Table Caption"}`<br>`**Table 1.** *Title*`<br>`:::` | `Table Caption` | **必须显式包裹**。Pandoc 无法自动识别紧邻表格上方的段落为题注，不包裹会被默认赋予 `Body Text`（与正文同大，如 12pt）。 |
| **表格注释** | `::: {custom-style="Table Note"}`<br>`*Note:* Explanations...`<br>`:::` | `Table Note` | **必须显式包裹**。同上，Pandoc 无法识别下方段落为表注，不包裹会落入 `Body Text`。 |
| **图片及题注** | `![**Figure 1.** *Title*](path)` | `Image Caption`<br>+ `Captioned Figure` | **使用原生语法，严禁外层套 `:::` 围栏**。Pandoc 原生将图片 alt 文本映射为 `Image Caption` 样式并赋予图段 `Captioned Figure`（居中）。若外加块级围栏，会破坏 Pandoc 的图段流，造成图片居中失效。 |

**内联格式控制（加粗与斜体）**：
- 题注中的局部排版（如编号加粗 `**Table 1.**` / `**Figure 1.**`，题名斜体 `*Title*`，注释前缀 `*Note:*`）直接在 Markdown 源码中书写。Word 导出后会忠实保留内联标记。
- 保证图表题注风格统一（例如图名与表名均采用“编号加粗、题名斜体”或均不加粗），源码撰写时即应保持一致。
- 门禁机制：被拦下的只有**样式名**——导出前 `check_md.py` 校验 `custom-style` 在模板中存在（拼错会静默建空壳样式），导出后 `audit_export.py` 对账 `word/styles.xml` 的样式定义。**「题注有没有被包裹」本身没有门禁**：判据立不住（正文句同样可能以「表 N」起头），漏包裹在产物里表现为 `Body Text`（与正文同大），靠 §2.4 渲染抽查核对。

## 2. 脚本概览

脚本位于本技能 `scripts/` 目录下，详细用法见各脚本的 `--help` 输出。

### 2.1 scripts/export.sh

一键导出主脚本：Markdown → Word (docx)，统一入口为 `bash <技能目录>/scripts/export.sh`。

**关键行为**：
- 自动处理工作目录与相对路径（确保 `.bib` 及图片路径正确解析）
- **图片路径**：绝对路径与相对路径都支持。导出时自动追加
  `--resource-path "<输入目录>:<git 项目根>:/"`——根目录 `/` 让绝对路径（`/Users/...`）直接解析
  （否则会被当成 `./Users/...`），git 项目根让「相对项目根」的路径（如 `figs/x.png`）也可解析。
  **无需在 YAML 里配 `resource-path`**
- 原生由 Quarto 渲染，支持 `{width=Xcm}` 属性语法与现代学术扩展
- 支持 `.markdown` 后缀（与 `.md` 同等待遇）
- **内置 CSL 自动寻路**：若 YAML `csl:` 填写本技能 `resources/csl/` 下的文件名（如 `apa.csl`），脚本自动解析并挂载技能内置 CSL 绝对路径，无需手动拷贝 `.csl` 文件
- **引用默认可点击**：`export.sh` 会给每篇稿件带上 `-M link-citations=true`，正文引用在 docx 里落成指向文末条目的内部书签链接。稿件 YAML 里写 `link-citations: false` 可关掉（实测 YAML 覆盖命令行，命令行只是默认值）
- **模板从哪来**：优先级 `-r` 显式指定 → `--preset` 显式指定 → 同目录唯一的 `.txt` → 内置默认预设
  `presets/zh-academic.txt`（见 §2.2）。拿到要求文件后**当场生成临时模板**，导出完即清理——配置一改模板自动跟着变，二进制模板不必入库。显式传 `-t`
  则以那一份为准（目标方自己发的 `.docx` 走这条），此时不套预设。同目录有多个 `.txt` 时直接报错，不替你猜
- 依赖 Quarto 渲染器（要求 >= 1.4）
- 其余参数见 `bash scripts/export.sh --help`：`--preset zh-academic|en-nature` 选内置预设（`-r` 优先）；`--strip-comments` 先去 HTML 注释再导出；`--no-check` / `--no-postflight` / `--no-audit` 分别关掉三道闸门（**不推荐**——关掉等于把静默失败的判读交回人眼）；`--eq-number-style cjk` 用中文编号写法。
- **产物完整性闸门（默认开）**：稿件里每个三位以上小数都必须出现在 docx 里，缺一个即
  阻断导出（`post_flight_check.py`）。这是导出链上唯一的数据丢失守护——后处理
  （公式重构）历史上丢过段。逃逸 `--no-postflight`（不推荐）
- `--pdf`：**可选**，导出后顺带用本机 Word 渲染一份同名 PDF（调 `render_via_word.sh`，见 §2.4）。
  **定位是「抽查核对」，不是「每次导出都跑一遍」**——docx 才是交付物；PDF 只在需要
  亲眼确认版式时出（如首次套用新模板、改了样式、要核对目录/页眉章名/页码这些**域**）。
  日常改字改句的重导出不必加它。
  **macOS 专用**——非 macOS 或未装 Word 时只打印一行提示并跳过，**docx 不受影响**；
  PDF **跳过**返回退出码 3（成功为 0），**渲染失败**返回 1——两者要分开判：3 = docx 已正常生成、只是没出 PDF；1 = 出了错

### 2.2 scripts/generate_template.py

从文字版格式要求生成 Word reference.docx 模板。

**关键行为**（底模、主题属性净化、单节校验、pgSz/pgMar、原生图语法居中等生成机制见 `design.md §1`）：
- 支持三线表/全网格线/顶底线/无边框四种表格样式（在 requirements.txt 的 `表格：...` 行声明，如 `表格：居中 三线表`）
- **支持表格内格式**：三线表线宽可调（`线宽上1磅 线宽底1磅 线宽表头下0.25磅`）、单元格垂直对齐、`表头：` 行单独设表头行字体字号加粗与跨页重复标题行
- **支持页眉 / 页脚 / 页码**：`页眉：`/`页脚：` 设样式，`页眉内容：`/`偶数页页眉内容：`/`首页页眉内容：`/`页脚内容：` 等设内容，`页码：阿拉伯 起始1` 设格式与起始页。内容支持 `{页码}` `{总页数}` `{样式标题:<样式名>}` 三种域
- 支持全面自定义各样式加粗与倾斜属性（自由写"加粗/不加粗"与"倾斜/不倾斜"），完美契合不同期刊与学位大论文的差异化规范要求
- 支持解析段前/段后间距

**调用方式**：格式要求只从文件读——每次生成都对应一份落盘的 `requirements.txt`，
这样"这份模板是按什么要求生成的"随时可查。

```bash
python3 scripts/generate_template.py requirements.txt -o template.docx
```

纸张尺寸不用命令行参数，只能由 requirements 文件的 `纸张：A4|Letter` 行设定（见 §1.5 表的「纸张」行；不写默认 A4）。

### 2.3 scripts/check_md.py

导出前校验脚本：检查 MD 中可能导致"静默失败"的写法。由 export.sh 在导出前自动执行（`--no-check` 可跳过，不推荐）。

**校验项**（18 项）：
- YAML 中 bibliography / csl 路径是否存在（`csl` 支持自动回退匹配本技能 `resources/csl/` 目录）
- 标准 Markdown `![]()` 和 `[]()` 中路径是否含空格（空格违反 URL 规范，Pandoc 静默失败）
- `![](path)` 图片文件是否存在（Pandoc 静默失败，图不会出现在 docx 中）
- Obsidian `![[path]]` 图片语法和 `[[link]]` 链接语法（Pandoc 不识别，漏成文本）
- `\newpage` / `\pagebreak` / `\clearpage`（docx 中不生效，分页用 `{{< pagebreak >}}`）
- `\tag{}` 公式编号（不是 Pandoc 语法，会让整条公式退化成字面文本）
- `custom-style="X"` 是否在模板中存在（按样式名或 styleId 匹配；不存在则 Pandoc 静默建空壳样式）
- **块级标记与正文没隔空行**（公式／`:::` 围栏／表格／图片行）
- **白名单外的短代码**（Quarto 只打一行 WARNING 便把整段标记丢弃，标记凭空消失）
- **标题层级与包裹规范**（拦截 `::: {custom-style}` 内误写 `#`、首个标题非 1 级、标题跳级、章节编号深度与 `#` 数量不匹配）
- **稿件用到、格式要求却没声明的深层样式**（三~六级标题／目录／引用块——不声明就静默回退底模默认，只有给了 `-r` 才查）
- **分节标记之后紧跟 `{{< pagebreak >}}`**（分节符已自带下一页，会多顶出一页）
- **中文稿用了 `{#eq-/fig-/tbl-}` 交叉引用、YAML 却没写对应的 `crossref` 前缀**（会渲染成中英混排的 `Equation 1`）
- **表格各行列数不一致**（pandoc 不报错，直接把多出来的单元格连同内容丢掉）
- **图片声明宽度超过版心**（pandoc 按 `pgSz - pgMar` 静默钳成版心宽，写 `{width=25cm}` 拿到的是 15.92cm）
- **正文引用的文献 key 在 `.bib` 里找不到**（产物里渲染成 `[key?]`，且该条不进参考文献列表；citeproc 只打一行 WARNING）
- **正文有引文语法、YAML 却没声明 `bibliography:`**（pandoc 完全不处理引文，`[@key]` 会**原样印进正文**）
- **正文引用的 crossref 标签没有 `{#标签}` 定义**（产物里渲染成 `?@标签`；Quarto 只打一行 WARNING）

> **兜底情况不一**，别一概而论：第 1 项与第 3 项 `export.sh` 另有一层以渲染器自己警告为准的
> 兜底（`Citeproc: citation … not found` / `Unable to resolve crossref`）；**第 2 项没有**——
> 实测没声明 `bibliography:` 时 citeproc 一声不吭，只有导前预检这一道。
> 导前预检可用 `--no-check` 跳过，兜底那层不能，所以「跳过预检」不等于「不检查」——
> 但**跳过预检会丢掉第 2 项这唯一一道防线**。

**调用方式**：
```bash
# 基本校验（不查模板样式）
python3 scripts/check_md.py 稿件.md

# 同时校验 custom-style 是否在模板中存在、稿件用到的深层结构样式是否已声明
python3 scripts/check_md.py 稿件.md -t template.docx -r 格式要求.txt
```

### 2.4 scripts/render_via_word.sh 与视觉抽查规范（macOS）

用本机 Microsoft Word 把 docx 渲染成 PDF，**导出后核对视觉效果与展开动态域的唯一可靠通道**。

```bash
# 单独跑
bash scripts/render_via_word.sh 正文.docx /tmp/正文.pdf

# 或挂在导出后面（结果相同，省一次手输）
bash scripts/export.sh 稿.md -o 正文.docx --pdf    # 同目录唯一 .txt 即格式要求，模板自动生成
```

#### 视觉核验轻重平衡 SOP

全篇几十页逐页翻看极其低效，每次微调一个错字就调 Word 渲染更是资源浪费。遵循以下分级策略：

1. **触发时机矩阵**：
   - **免渲染（Skip）**：纯文字润色、错别字修正、未触碰模板样式的微调，仅依赖 `audit_export.py` XML 静态对账，不跑渲染；
   - **局部按需（Conditional）**：修改了 `requirements.txt` 模板、重构了大表格、插入了多行长公式或更换了 CSL，跑渲染并定向查看受影响页面；
   - **投稿强制（Mandatory）**：**正式提交前**必须跑一次完整 Word PDF 渲染并完成 4 点拓扑抽查验收（与 `SKILL.md §三 2` 同一口径；日常导出不必跑）。

2. **4 点拓扑抽样策略（拒绝全量翻页，直击 4 个风险截面）**：
   - **① 首页元数据与开篇（第 1 页）**：核对大标题居中、Abstract 居中与正文两端对齐、Keywords 独立成行、章节首段不缩进与次段缩进对比、首页页眉页脚隐藏/显示；
   - **② 最宽/最复杂的表格页（如 Table 1 / 回归总表）**：核对三线表两端在版心之内（绝不超出右边距）、表内数字小数点/居中对齐、无跨页乱断行、长表跨页表头重复；
   - **③ 公式与图表密集页**：核对数学公式居中且编号靠右、图片居中无变形且无多余表格边框伪影。若因图片过大被挤至下页导致前页产生大面积断层留白，可通过**调小图片宽度 `{width=Xcm}`**（使图收纳在本页）或**在图前丰富扩充正文段落**（使页面排满并自然溢出）两种方式优化版面节奏；
   - **④ 参考文献起始与转折页（域展开与孤行）**：
     - **动态域有效性**：页眉章名（`STYLEREF`）是否正确显示（**绝不能出现 Word 域错误「错误!未找到引用源」**）、页码（`PAGE`）是否正常编号；
     - **排版形态**：参考文献条目悬挂缩进 0.5 英寸是否平整、尾页是否有单行孤行。

**Word 沙箱与中转机制说明**：
- **Word 是最终渲染器，也是唯一会把域真正展开的渲染器**——目录、页眉章名（`STYLEREF`）、页码（`PAGE`）都靠它出值。LibreOffice 不走沙箱，但域不展开，核对这些内容时不能用；
- **沙箱权限绕道**：Word for Mac 是沙箱应用，AppleScript 交给它容器外的路径时 macOS 会弹窗索权。脚本先把文件拷进 `~/Library/Containers/com.microsoft.Word/Data/` 再渲染，Word 对自己的容器有完全访问权，实现完全免弹窗静默渲染；
- **容器免残留**：中转文件带进程号（`_md2word_render_in.$$.docx` / `_out.$$.pdf`）防并发互踩，脚本退出或中断时 `trap` 自动清理，不留垃圾；
- **栅格化核对**：抽查页面转图使用 `pdftoppm`（poppler）。别用 PyMuPDF 做视觉核对（特定内嵌字体易报乱码）。

### 2.5 scripts/read_reference_docx.py —— 从参考 .docx 反推 requirements.txt 草稿

用户给了一份学校/期刊/单位的官方模板时走这条路（`SKILL.md §〇` 路径 A），**比人工对照模板抄格式准确**：

```bash
python3 scripts/read_reference_docx.py 参考.docx -o 名称_requirements.txt
```

读出的项：页面尺寸 / 页边距 / 页眉页脚距边界 / 页码格式与起始；各样式的中西文字体与字号、
加粗倾斜、对齐、行距（**倍数 / 固定值 / 最小值三态分得开**）、段前段后、缩进（**字符单位也读得到**）、
段落下边框；表格边框与表头行；页眉页脚内容与域。

**读不出来的项会列在草稿末尾的注释块里**，照着核一遍再当成品用。走纯 XML 而非 python-docx——
中文字体、字符缩进、行距类型在 API 层都够不着（原因见 `design.md §2.21`）。

### 3.5 新增 CSL 流程

Wiley 等未预下载的出版商，需从 Zotero 官方仓库下载并规范化：

python3 scripts/normalize_csl.py resources/csl/ --check

**`csl:` 路径写法**：
- **推荐直接写内置文件名**：如 `csl: apa.csl` 或 `csl: chinese-gb7714-2015-numeric.csl`，`scripts/export.sh` 和 `scripts/check_md.py` 会自动在技能自带的 `resources/csl/` 目录下查找并挂载；
- **自定义 CSL**：可放在稿件同目录下（写相对稿件目录的路径）或写绝对路径。
